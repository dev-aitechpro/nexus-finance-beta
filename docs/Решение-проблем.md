# Решение проблем NEXUS Finance

Практический справочник «что делать, если сломалось». Собирать каждую описанную здесь проблему заново дорого, а часть из них уже встречалась по ходу работы. Всё ниже проверяемо по коду репозитория. Пометка **требует проверки** означает: механизм правдоподобен и согласуется с кодом, но конкретный случай в этой среде не воспроизводился.

## 1. Как пользоваться

**«У меня симптом»** — найдите его в таблице §3 или §4 и перейдите в подраздел. **«У меня ошибка X»** — идите по разделам: 3 запуск, 4 данные, 5 производительность, 6 сборка, 7 dev-режим, 8 платформа, 9 сеть, 10 Android, 11 журнал, 14 публикация и обновления. Внутри подраздела всегда одно и то же: **симптом → причина → решение → проверка**.

Симптомы, которые видны **только на телефоне**, собраны отдельно: §10.5 (шесть
воспроизводимых признаков) и §10.6 (правки, которые не выглядят симптомом). В
десктопном браузере и в Electron их не воспроизвести — там нет ни `pointer:
coarse`, ни вырезов, ни кнопки «Назад».

Диагностика ничего не портит: все команды ниже только читают — `check-desktop-db.mjs` прямо оговаривает «скрипт строго читающий: он не пишет, не переименовывает и не создаёт файл БД», то же для `check-dist.mjs` и `check-file-protocol.mjs`. Единственное место, удаляющее файл базы, — обработчик `clear-db` в `electron-main.cjs`, и он вызывается только из кнопки очистки. Состояние меняют `npm run build` (перезаписывает `dist/`), `npm run coverage`, `npm run map`, кнопка «Очистить все данные» и `npm run dev:desktop` (сборка + запуск Electron).

## 2. Первые проверки

Выполняйте до любых догадок — вместе они закрывают почти все сбои сборки и хранилища.

```powershell
npm run typecheck    # tsc --noEmit — ошибки типов в src/ и tests/
npm test             # vitest run — 84 теста в 3 файлах
npm run build        # vite build -> dist/index.html (~2.9 МБ)
npm run verify:dist  # артефакт собран правильно
npm run verify:file  # бандл живёт под протоколом file://
npm run verify:db    # рабочая база в профиле пользователя читается
```

- `typecheck`: `tsconfig.json` включает `src` и `tests`, но исключает `src/hooks/useKeyboard.ts` и `src/lib/engine1.ts` (JSX внутри `.ts`).
- `test`: 84 теста — `animations.test.ts` 16, `storage.test.ts` 58, `subscriptions.test.ts` 10; код возврата 1 при падении любого.
- `build`: нет `dist/index.html` — Electron даст белое окно (§3.3).
- `verify:dist` и `verify:file` ловят разные классы дефектов (§6.1–6.2). Учтите: `npm run verify` = `test && build && verify:dist` и **не** включает `verify:file` — запускайте его отдельно.
- `verify:db`: единственный способ убедиться, что приложение писало данные на диск; файл базы появляется только после первого автосохранения.

## 3. Приложение не запускается (Electron)

| № | Симптом | Суть |
|---|---------|------|
| 3.1 | `Electron failed to install correctly…` | бинаря нет |
| 3.2 | `electron .` не стартует | нет поля `main` |
| 3.3 | Белое пустое окно | нет `dist/index.html` |
| 3.4 | Второй запуск мгновенно завершился | single-instance lock |
| 3.5 | Лишнее окно консоли / нет инспектора | цепочка npm; нужен `--dev` |
| 3.6 | Нет `window.electronAPI` | `preload.cjs` не выполнился |

### 3.1 Нет бинаря Electron

**Симптом.** `npm run electron` → `Electron failed to install correctly. Please delete node_modules/electron and run "npx install-electron --no" manually.`

**Причина.** Пакет ставился с `ELECTRON_SKIP_BINARY_DOWNLOAD`: нет `node_modules/electron/dist` и нет `path.txt`. `node_modules/electron/index.js` читает `path.txt`, при отсутствии зовёт `downloadElectron()`, установщик падает (сети нет) — и модуль бросает это исключение.

**Решение.** 1) Версия: `node -p "require('./node_modules/electron/package.json').version"`. 2) Скачать `https://mirrors.huaweicloud.com/electron/v<верс>/electron-v<верс>-win32-x64.zip` (зеркало рабочее, §9) и распаковать **содержимое** архива в `node_modules\electron\dist`. 3) Создать `node_modules\electron\path.txt` со строкой `electron.exe`. Альтернатива — `ELECTRON_OVERRIDE_DIST_PATH`: `index.js` (строки 30–32) при ней возвращает `<значение>/<содержимое path.txt>` и не проверяет существование файла; если `path.txt` нет, подставляется имя `electron` без расширения — запуск через него на Windows требует проверки, поэтому основной путь — `path.txt`.

**Проверка.** `Test-Path node_modules\electron\dist\electron.exe` и строка `[main] Electron 43.x / Node … / Chromium …` из `reportStartup()`.

### 3.2 Нет поля `main` в `package.json`

**Симптом.** `npm run electron` завершается ошибкой, окно не появляется.

**Причина.** Electron не знает, что исполнять. Поле отсутствовало вовсе — это была первая причина, почему проект не запускался на ПК (`docs/Выполнение-ТЗ.md` §0б).

**Решение.** `"main": "electron-main.cjs"` в `package.json` (сейчас так); для сборки то же в `build.extraMetadata.main`.

**Проверка.** `node -p "require('./package.json').main"` → `electron-main.cjs`.

### 3.3 Пустое белое окно

**Симптом.** Окно открылось, но белое.

**Как проявляется сейчас.** Приложение сообщает о причине само: в терминал и в журнал уходит `dist/index.html не найден — выполните npm run build…`, а в окно грузится страница «NEXUS Finance: нечего запускать» с ожидаемым путём. Это `reportStartup()` и `showStartupError()` (`electron-main.cjs`, строки 98–113, 360–374).

**Причина.** `electron .` открывает `dist/index.html` по `file://` через `win.loadFile()`. Сборки не было.

**Решение.** `npm run build`, затем `npm run electron:debug`.

**Проверка.** `npm run verify:dist` печатает размер файла; в журнале `[main] рендерер загружен: file:///…/dist/index.html`.

### 3.4 Второй запуск завершается, второго окна нет

**Симптом.** `npm run electron` отрабатывает мгновенно. Из терминала при этом печатается `[main] !! приложение уже запущено — второй экземпляр закрыт`; у собранного приложения (окна консоли нет) это выглядит как «ничего не произошло».

**Причина.** `app.requestSingleInstanceLock()` (`electron-main.cjs`, строка 484) — защита от того, чтобы второй экземпляр переписал файл БД последним снапшотом. Отдельный случай: процесс живёт с треем и без окна (`window-all-closed` не выходит, пока `tray` существует) и держит блокировку невидимо.

**Решение.** 1) Проверить трей: клик открывает окно, правый клик → «Выход». 2) Значок уехал в переполнение — `Get-Process electron -ErrorAction SilentlyContinue | Stop-Process`. 3) Убедиться, что не осталось процесса без окон и без трея: в коде для этого есть проверка — `set-tray(false)` при `BrowserWindow.getAllWindows().length === 0` вызывает `app.quit()` с записью `окон нет и трея нет — выходим, чтобы не остаться невидимым процессом`.

**Проверка.** `Get-Process electron` пуст, следующий запуск открывает окно.

### 3.5 Лишнее окно консоли и/или нет инспектора

**Симптом (а).** Кроме окна приложения появляется чёрное окно консоли. **Симптом (б).** `npm run electron:debug` запущен, окно инспектора нет.

**Причина (а).** Это `cmd.exe`/`node.exe` из цепочки npm → `electron` → бинарь, а не приложение. Сам `electron.exe` — GUI-сборка (PE Subsystem = 2, WINDOWS_GUI) и при прямом запуске окна консоли не создаёт. В собранном приложении консоли нет вовсе, поэтому вывод в stdout просто исчезает — потому в `electron-main.cjs` всё важное дублируется в файл журнала.

**Причина (б).** `const DEBUG` (`electron-main.cjs`, строка 66) — только явный флаг `--dev` или `NEXUS_DEVTOOLS=1`; «всегда включено» нет намеренно. И даже с флагом инспектор открывается **после** `did-finish-load`, иначе откроется на пустом документе (строки 460–465).

**Решение (а).** Чистый вывод — запуск бинаря напрямую, минуя npm: `$env:NEXUS_DEVTOOLS = "1"`, затем `& .\node_modules\electron\dist\electron.exe .` **Решение (б).** `npm run electron:debug` (это `electron . --dev`) либо `$env:NEXUS_DEVTOOLS=1; npm run electron`.

**Проверка.** Окно консоли не появляется, окно приложения открывается; в журнале `[main] открываю инспектор (--dev / NEXUS_DEVTOOLS=1)`.

### 3.6 `window.electronAPI` не появился

**Симптом.** Приложение открылось, но «мост сломался»: нет строки `[preload] window.electronAPI готов`, хранилище не то, что ожидает рендерер.

**Причина.** Синтаксическая ошибка в `preload.cjs` или неверный путь к нему. `reportStartup()` предупреждает об отсутствии файла, а `webContents.on('preload-error')` пишет `preload не выполнился (<путь>): <ошибка>`. При `sandbox: true` из preload доступны только `require('electron')` и модули песочницы (`events`, `timers`, `url`) — `fs` и `path` недоступны, вся работа с диском в main-процессе.

**Решение.** `node --check preload.cjs`; логику диска переносить в `electron-main.cjs`, в preload добавлять только `contextBridge`.

**Проверка.** В журнале `[preload] window.electronAPI готов (sandbox: true, contextIsolation: true)`.

## 4. Запускается, но данные или функции не работают

| № | Симптом | Суть |
|---|---------|------|
| 4.1 | Тост «Не удалось прочитать базу… Данные не перезаписаны» | файл базы есть, но не читается: `load-db` бросает исключение |
| 4.2 | «Последняя запись не удалась», `sqlite · временное` | ошибка снапшота не дошла до диска |
| 4.3 | Данные пропали в браузере | очистка данных сайта удалила IndexedDB |
| 4.4 | Любая правка падает, «база новее приложения» | `schema_version` выше `SCHEMA_VERSION` |
| 4.5 | Всё пропадает при перезапуске | `init()` упал, подставлен `MemoryStorage` |

### 4.1 База не читается, автосохранение заблокировано

**Симптом.** Данные не загрузились, всплывает тост `Не удалось прочитать базу: … Данные не перезаписаны.`, в «Настройках» → «Хранилище данных» красная плашка и ссылка «Повторить чтение».

**Причина.** Цепочка (и это защита от потери данных): 1) `SqliteStorage.open()` (`src/storage/sqlite.ts`) → `snapshots.load()` → `ElectronSnapshotStore.load()` → IPC `load-db`; 2) `load-db` (`electron-main.cjs`, строки 138–151) отдаёт `null` **только если файла нет** (первый запуск), а если файл есть и не читается — **бросает исключение** с записью в журнал; 3) `open()` ставит `readError` и `lastPersistOk = false` и логирует `[storage] сохранённая база не прочитана:`; 4) `storageService.load()` (`src/lib/storage.ts`) **пробрасывает** ошибку, а `AppProvider` (`src/hooks/AppProvider.tsx`, строки 95/113/158) ставит `loadBlocked` и показывает тост — пока флаг установлен, автосохранение выходит рано, иначе пустое состояние затёрло бы реальные данные.

**Решение.** 1) `npm run verify:db` — покажет, на каком шаге сломался файл. 2) **Скопировать файл до любых действий:** `Copy-Item "$env:APPDATA\nexus-finance\nexus-data.sqlite" "$env:USERPROFILE\Desktop\nexus-backup.sqlite"`. 3) Убрать блокировку: закрыть Проводник на папке данных, снять антивирусную блокировку, проверить права на запись и свободное место. **Требует проверки** — конкретная причина на конкретной машине не воспроизводилась. 4) Если файл битый — восстанавливать из копии п.2: приложение такой файл не починит, а начнёт с чистой базы (`sql.reinit()` в `open()`). 5) После устранения причины нажать «Повторить чтение» (`retryLoad`).

**Проверка.** `npm run verify:db` печатает `Итог: ✓ база читается, схема v1, все 8 таблиц данных…`; плашка пропала; данные появились.

### 4.2 «Данные во временном хранилище»

**Симптом.** В настройках статус `Последняя запись не удалась — хранилище считается временным` либо `Данные во временном хранилище — сохраните резервную копию`, плашка `Последняя запись не сохранена: <текст>`, строка «Хранилище» — `sqlite · временное`.

**Причина.** `SqliteStorage.persist()` (`src/storage/sqlite.ts`, строки 554–573) ловит ошибку снапшота, ставит `lastPersistOk = false` и `lastPersistError`; геттер `persistent` (строки 229–232) возвращает `false`, и `describeStorage()` (`src/storage/index.ts`, строки 133–137) печатает этот статус. Данные в памяти есть, на диск не попали — экспорт нужен немедленно.

**Решение.** Читать текст ошибки, а не угадывать:

| Текст ошибки | Что означает | Что делать |
|--------------|--------------|------------|
| `main-процесс не смог записать файл базы` | `save-db` вернул `false`; причина в журнале: `не удалось сохранить файл базы <путь>: <…>` | смотреть журнал (§11) |
| `не удалось сохранить базу: …; резерв: …` | браузерная ветка: не сработала ни IndexedDB, ни localStorage | см. §4.3 |
| `EPERM` / `ENOSPC` | нет прав на запись либо кончилось место | проверить место и права. **Требует проверки** — код ошибки на этой машине не фиксировался |

**Проверка.** Внесите любую правку: должно стать `sqlite · постоянное`, статус — `Данные в SQLite — переживают перезапуск и чистку кэша`.

### 4.3 Данные пропали в браузере / WebView

**Симптом.** База была, после очистки данных сайта её нет. На Android то же самое делает очистка данных приложения.

**Причина.** Вне Electron снапшот лежит в IndexedDB (`createSnapshotStore()`, `src/storage/snapshots.ts`, строки 279–286): приоритет — файл в `userData` (Electron) → IndexedDB → localStorage (запасной вариант) → память. Очистка данных сайта удаляет и IndexedDB, и localStorage. Второй путь, раньше не замеченный: приложение Android попадало в **Google Backup** и могло восстановить базу на другом устройстве молча — теперь бэкап запрещён (`allowBackup="false"` плюс `res/xml/{data_extraction_rules,backup_rules}.xml`), см. §10.5.6 и §10.4.

**Решение.** Восстановить из экспорта JSON (Настройки → Импорт) и делать его регулярно: удаление данных из браузера необратимо, а на Android другого пути восстановления теперь нет вообще — экспорт обязателен, а не рекомендация.

**Проверка.** `npm run dev`, внести данные, обновить страницу — записи на месте (заодно видно, разрешён ли IndexedDB; приватный режим может его отключать — **требует проверки**). Для Android: `adb shell bmgr list-backup-preds | findstr nexus` должен быть пуст.

### 4.4 Запись отключена: база из более новой версии

**Симптом.** Данные читаются, любое изменение падает, в настройках плашка со схемой.

**Причина.** `SqliteStorage.open()` (строки 274–283) сравнивает `meta.schema_version` с `SCHEMA_VERSION`; при версии выше выставляется `locked`, и `assertWritable()` (строки 498–500) бросает исключение на каждой записи — старый DDL разошёлся бы с миграциями новой версии.

**Решение.** Вернуться к версии, создавшей базу, сделать экспорт, и только потом обновляться; чистую базу — только после экспорта.

**Проверка.** `npm run verify:db` сравнивает версию в базе с `SCHEMA_VERSION` из `src/storage/schema.ts` и печатает расхождение.

### 4.5 SQLite не инициализировался, работает память

**Симптом.** Приложение работает, но при перезапуске всё пропало; в консоли `[storage] SQLite недоступен, работаем в памяти: …`.

**Причина.** `createStorageAdapter()` (`src/storage/index.ts`, строки 23–39) ловит ошибку `init()` и подставляет `MemoryStorage`, чтобы приложение осталось рабочим; текст ошибки доступен через `sqliteInitError()`. Типичный источник — WASM: `browserSqlJsLoader` (`src/storage/sqlite.ts`, строки 42–54) сначала пробует `sql-wasm` с `wasmBinary` из `src/storage/wasmAsset`, при неудаче откатывается на `sql-asm`.

**Решение.** Смотреть исходную ошибку в консоли рендерера. Если есть `[storage] sql.js/wasm недоступен…` — сборка ушла на запасной путь, см. §6.3 и §7.3.

**Проверка.** В настройках «Хранилище» — `sqlite`, а не `memory`.

## 6. Сборка и артефакт

### 6.1 `npm run verify:dist` (`scripts/check-dist.mjs`)

| Проверка | Симптом, если сработала |
|----------|-------------------------|
| `dist/index.html` есть, печатает размер | нет сборки — белое окно (§3.3) |
| Нет голых импортов node-модулей (`fs`, `path`, `child_process`, `electron`, `os`, `crypto`, `net`, `http`) | страница падает с `TypeError: Failed to resolve module specifier "fs"` |
| Есть `<title>NEXUS Finance</title>` | собран не тот входной HTML (§6.5) |
| Нет внешних `<script src>` / `<link rel=stylesheet>` | сборка не single-file: в установленном приложении файлов рядом не будет |
| Все локальные ссылки физически есть в `dist/` | 404 под `file://` — молча, без внятной ошибки |

**Как чинить.** Голые импорты даёт только `build.rollupOptions.external` в `vite.config.ts` — его там быть не должно (предупреждение-комментарий в самом конфиге; дефект №1 в §8 `docs/Выполнение-ТЗ.md`). Внешние js/css — проверьте, что в `build.plugins` остался `viteSingleFile()`. Отсутствующие файлы — в `public/` (сейчас только `favicon.ico`). Код возврата 1 при провалах.

### 6.2 `npm run verify:file` (`scripts/check-file-protocol.mjs`)

Проверяет, что бандл живёт под `file://` — так его грузит `win.loadFile(dist/index.html)`. Каждая находка печатается с номером строки, столбцом и смещением в файле.

| Правило | Что ломается под `file://` |
|---------|---------------------------|
| `attr-abs` / `attr-missing` | `src="/assets/app.js"` резолвится от корня диска (`C:\assets\app.js`); относительная ссылка без файла грузится молча |
| `js-abs-url` / `css-url` | `src = "/…"` в строковых литералах; `url(/img/x.png)` в CSS |
| `fetch-abs` | `fetch("/data.json")` уходит в `file:///C:/data.json` и не проходит |
| `dyn-import` | `import("/chunk.js")`, `new Worker("/w.js")`, `importScripts("/…")` |
| `new-url-origin` | `new URL(x, location.origin)` бросает `Invalid URL`: origin у `file://` — строка `"null"` |
| `new-url-abs` | абсолютный путь первым аргументом — база отбрасывается, путь уходит в корень диска |
| `new-url-rel` (предупреждение) | `new URL(x, location.href)` корректно только с относительным `x` |
| `dev-host` / `dev-port` | следы `localhost:5173`, `127.0.0.1` в прод-сборке |
| `sw-abs` | `serviceWorker.register("/sw.js")` на `file://` — всегда `SecurityError` |
| `base-url` / `assets-abs` | следы `base: "/"`: `BASE_URL` по умолчанию равен `"/"`, склейка даёт путь от корня диска |

Плюс замечания, не влияющие на код возврата: внешние ресурсы, реально грузящиеся по сети; число вхождений `import.meta.url`; значение `base` из `vite.config.ts`. **Как чинить.** Почти всё лечится относительными путями. `base: "./"` в `vite.config.ts` задан явно — раньше его попутно выставлял `viteSingleFile()`, и полагаться на побочный эффект чужого плагина нельзя: стоит отключить single-file (или добавить ассет, который не вшивается) — и абсолютный base уведёт ссылки от корня диска, что ломает и `file://` в Electron, и WebView контейнера Capacitor (`https://localhost`). Код возврата 1 при ошибках, предупреждения допустимы.

### 6.3 CSP блокирует скрипт, WASM или воркер

**Симптом.** В консоли `Refused to … violates the following Content Security Policy directive`; отдельно — предупреждение Electron `Insecure Content-Security-Policy`, если политики в документе нет вовсе.

**Причина.** Политику добавляет плагин `cspPlugin` из `vite.config.ts` **только при сборке** (`apply: "build"`, чтобы не сломать HMR). Она намеренно жёсткая: `default-src 'none'`, дальше точечные разрешения (комментарий в конфиге, строки 12–27):

| Токен | Зачем |
|-------|-------|
| `'unsafe-inline'` в `script-src` | весь бандл лежит inline в `index.html` |
| `'wasm-unsafe-eval'` | без него блокируется компиляция `sql.js` |
| `blob:` / `data:` | воркер `tesseract.js`, wasm и шрифты приходят как `data:` |
| `file:` | под `file://` origin `'self'` не совпадает с файловыми URL |
| `https://cdn.jsdelivr.net` в `connect-src` | за сами данные: wasm-ядро и `*.traineddata`, их грузит сам воркер |
| `https://cdn.jsdelivr.net` в `script-src` | воркер `tesseract.js` создаётся из `blob:`-URL, а его тело делает `importScripts("https://cdn.jsdelivr.net/…/worker.min.js")`; `importScripts` внутри воркера проверяется по `script-src` унаследованной им политики |

**Решение.** Новый внешний ресурс не загрузится молча — разрешите его явно: другой CDN → в `connect-src`, внешний шрифт → в `font-src`, изображение → в `img-src`. Исключение — скрипты, которые тянет **воркер** через `importScripts`: им нужен ещё и `script-src`, иначе воркер не стартует. Именно так был сломан `tesseract.js` до добавления хоста в `script-src` — одинаково под `file://` в Electron и под origin `https://localhost` в контейнере Capacitor.

**Проверка.** `npm run build && npm run verify:file`, затем `npm run electron:debug` и вкладка Console: строк `violates the following Content Security Policy` быть не должно.

### 6.4 Артефакт собран, но не грузится

**Решение.** 1) `npm run verify:file`. 2) Если ошибок нет — смотреть в журнале `[main] !! страница не загрузилась: <описание> (<код>) — <url>`: обработчик `did-fail-load` (`electron-main.cjs`, строки 443–447) печатает код и URL. Там же ловятся `[main] !! процесс рендерера завершился: <reason>` и `[main] ! рендерер не отвечает — интерфейс может быть заморожен`.

**Проверка.** `[main] рендерер загружен: file:///…/dist/index.html`.

### 6.5 Собрали dev-конфигом вместо прод-конфига

**Симптом.** `verify:dist` ругается на заголовок; в сборке нет CSP; в интерфейсе есть отладочная панель `DevTools`.

**Причина.** `npm run build` = `vite build` (конфиг по умолчанию — `vite.config.ts`, вход `index.html`, CSP-плагин, скрипт `src/main.tsx`). У `vite.dev.config.ts` вход — `index.dev.html` со скриптом `src/main.dev.tsx` и без `cspPlugin`; заголовок там `NEXUS Finance (Dev)`, а `check-dist.mjs` ищет ровно `<title>NEXUS Finance</title>`.

**Решение.** Всегда `npm run build`, а не `vite build --config vite.dev.config.ts`.

**Проверка.** В `dist/index.html` есть `<meta http-equiv="Content-Security-Policy">` и заголовок `NEXUS Finance`.

## 8. Специфика платформы

Выбор моста — `detectPlatform()` / `platform()` (`src/platform/index.ts`): `detectWindows()` → `detectAndroid()` → userAgent. `detectWindows()` срабатывает по наличию `window.electronAPI`, поэтому в обычном браузере на Windows мост всё равно веб-версии.

| Возможность | Electron | Браузер / WebView |
|-------------|----------|------------------|
| Хранилище | файл `nexus-data.sqlite` в `userData` | IndexedDB → localStorage → память |
| Экспорт/импорт | `dialog.showSaveDialog` / `showOpenDialog` | `<a download>` и `<input type=file>`; в контейнере Capacitor — `@capacitor/filesystem` + `@capacitor/share` |
| Уведомления | `Notification` в main-процессе | `new Notification()` (нужно разрешение); в контейнере — `@capacitor/local-notifications` |
| Значок в трее | есть (`features.tray: true`) | нет (`features.tray: false`) |
| Папка с данными | открывается Проводником | в APK пункта нет (`features.dataFolder: false`), показан настоящий адрес хранилища |
| Кнопка «Назад» | нет (`features.backButton: false`) | в контейнере Capacitor — `App.addListener("backButton")`; в браузере нет |
| Версия приложения | `app.getVersion()` | константа `1.0.0` из бандла; в APK — `versionName` из манифеста |

Мосты деградируют прозрачно: `createElectronBridge()` при отсутствии нужного IPC откатывается на веб-реализацию, чтобы мост никогда не бросал исключений. Поэтому «работает, но как в браузере» означает «нет соответствующего IPC» — проверьте §3.6.

**Значок в трее.** Переключатель в настройках есть только при `features.tray`. `set-tray(false)` идемпотентно возвращает `true`; `set-tray(true)` требует `public/favicon.ico`, иначе `false` и `[main] !! иконка трея не найдена: …` (окно при этом всё равно открывается). При выключенном трее и закрытом окне приложение завершается (`window-all-closed` → `app.quit()`), при включённом — остаётся жить, отсюда §3.4.

**Уведомления.** Обработчик `notify` в главном процессе проверяет `Notification.isSupported()`; при отказе пишет `[main] ! системные уведомления не поддерживаются — уведомление не показано`. В Windows дополнительно проверьте «Параметры» → «Уведомления» и «Не беспокоить». Но вызывается ли этот обработчик вообще — отдельный вопрос, см. «Системные уведомления» ниже.

**Экспорт/импорт.** Экспорт идёт через `platform().saveTextFile()` → `save-text-file`; `false` означает и отмену диалога, и ошибку записи — тип `Promise<boolean>` этого не различает, причину пишет main: `[main] !! не удалось записать файл <путь>: …`. Импорт: `null` от `pick-text-file` рендерер читает как отмену выбора, о нечитаемом файле main сообщает и пробрасывает ошибку. Строка `accept` (`"application/json,.json"`) превращается в нативный фильтр функцией `extensionsFromAccept()`; если диалог показывает все файлы — строка не дошла до `ipcRenderer.invoke`. Формат файла — `{app, version, exportedAt, data}` (`serializeExport` / `parseImport` в `src/lib/storage.ts`); чужой JSON даёт «Структура файла не похожа на бэкап NEXUS Finance».

**Кнопка «Назад» (Android).** Нативная подписка в приложении **ровно одна**: `usePlatformBackButton` (`src/App.tsx:65-100`) вызывается один раз, а решают `canHandle`/`onBack`: верхний открытый диалог из стека `useOverlayStack` → модалка транзакции (страховка) → возврат на главный экран; на главном экране `canHandle` возвращает `false`, и мост воспроизводит системное поведение сам (§10). Шторка «Ещё» в стек не встаёт: её закрывает приоритетный слот `backRouter.shell`, а нативная подписка заводится на уровне модуля в `AppShell.tsx` — **вторая подписка на `backButton` недопустима**: событие раздаётся всем подписчикам, а мост при возврате `false` вызывает выход из приложения (§10.6). В Android-контейнере подписка на `App.addListener("backButton", …)` работает; в обычном браузере на Android — нет, там моста Capacitor нет вовсе.

**Системные уведомления.** Мост `notify()` на Android реализован корректно (разрешение запрашивается, `isExactNotification: false`), но **приложение его нигде не вызывает**: все сообщения пользователю идут внутренними всплывающими подсказками через `notify()` из `AppProvider` (одноимённая функция состояния приложения не имеет ничего общего с методом `PlatformBridge.notify`). Поэтому разрешение `POST_NOTIFICATIONS` объявлено, а запроса не происходит, и системных уведомлений не приходит. Объявление в интерфейсе при этом честное: `features.notifications` считается по наличию плагина в сборке, а не жёстко `true`.

| Хост | Состояние |
|------|-----------|
| `registry.npmjs.org` | работает |
| `github.com`, `cdn.jsdelivr.net`, `mirrors.tuna.tsinghua.edu.cn`, `repo.maven.apache.org` | `ECONNRESET` (часть отвечает, но TLS рвётся при загрузке) |

Практический вывод: `npm install` из реестра проходит, всё, что с GitHub и CDN, — нет. Этим же объясняется, почему распознавание чеков на `tesseract.js` не работает офлайн: воркер и языковые данные приходят с `cdn.jsdelivr.net` — хост разрешён и в `connect-src`, и в `script-src`, но недоступен. Сборщику установщика и Gradle это не мешает: у них свои зеркала (`registry.npmmirror.com/-/binary/electron-builder-binaries/` и `maven-central.storage-download.googleapis.com`).

**Установка Electron через зеркало.** `$env:ELECTRON_MIRROR = "https://mirrors.huaweicloud.com/electron/"`, затем `npm install`. Не помогло — ручная распаковка по §3.1.

**`ECONNRESET` при загрузке.** Не переустанавливать всё подряд, а чинить конкретный шаг: бинарь Electron — зеркало `ELECTRON_MIRROR` или распаковка (§3.1); npm-пакеты — через реестр, при сбое конкретного tarball повторить `npm install` (сбой сетевой, а не файловый); Gradle/Maven — обход уже прописан зеркалом `maven-central.storage-download.googleapis.com` в `~/.gradle/init.d/` (`docs/Выполнение-ТЗ.md` §7). Проверка: `npm ls electron` показывает версию, `Test-Path node_modules\electron\path.txt` — `True`.

**`electron-builder` не собирает установщик.** Раньше он требовал сети, а доступен был только реестр npm, и сборка в `dist-electron` не проверялась. Сейчас есть `npm run build:win` (`scripts/build-windows.mjs`): скрипт ставит зеркало бинарей `ELECTRON_BUILDER_BINARIES_MIRROR`, берёт Electron локально (`build.electronDist`) и повторяет шаг до четырёх раз. **Требует проверки:** если сборка всё же падает, смотрите `builder-debug.yml` в `dist-electron` — туда `DEBUG=electron-builder` кладёт полный сгенерированный NSIS-скрипт. Для разработки и диагностики `dist-electron` не нужен: `npm run build` + `npm run electron:debug` дают то же самое.

### 10.1 Симптомы сборки

| Симптом | Причина и решение |
|---------|-------------------|
| `ToolchainProvisioningException: Cannot find a Java installation matching {languageVersion=21, …}` | Android Gradle Plugin берёт компилятор из тулчейна с `languageVersion = compileOptions.targetCompatibility`, а у Capacitor 8 это 21. Нужен физически установленный **JDK 21**; в системе обычно только 25. Положите JDK 21 в `%USERPROFILE%\.gradle\jdks\` или укажите путь в `NEXUS_JDK21` — `scripts/build-android.mjs` ищет его сам и передаёт `-Porg.gradle.java.installations.paths` вместе с `auto-download = false` |
| Gradle падает на резолве `kotlin-stdlib`, `org.apache.cordova:framework` и других артефактов Central | `repo.maven.apache.org` и `repo1.maven.org` в этой среде живут за локальным TUN (198.18.x.x) и рвут TLS-рукопожатие. Рабочее зеркало — `https://maven-central.storage-download.googleapis.com/maven2`; оно прописано в `android/settings.gradle` (`pluginManagement` и `dependencyResolutionManagement`) и продублировано в `buildscript.repositories` и `allprojects.repositories` корневого `android/build.gradle`. **Без зеркала сборка не пройдёт** |
| `must appear before any other statements` про `pluginManagement` | Gradle 9.3.1 требует, чтобы `pluginManagement` был **первым оператором** `settings.gradle`. Поэтому `include`-строки в файле стоят под ним, а не над |
| Репозиторий модуля игнорируется | `repositoriesMode = RepositoriesMode.PREFER_SETTINGS` перекрывает `repositories {}`, объявленные в `build.gradle` отдельных модулей (в том числе в `node_modules/@capacitor/android/capacitor/build.gradle`, который править нельзя). `FAIL_ON_PROJECT_REPOS` здесь не подошёл бы — он заставил бы вычищать чужие файлы |
| `Could not find method buildDir()` / ошибки на `rootProject.buildDir` | Свойство `Project.buildDir` удалено в Gradle 9. В шаблоне Capacitor 8 стоял Gradle 8.14.3, но скачать его нельзя (зеркала отдают HTML-заглушку на `/distributions/*.zip`), доступна только лежащая в кэше 9.3.1. Поэтому в `android/build.gradle` замена на `rootProject.layout.buildDirectory` |
| `Remote host terminated the handshake` на середине сборки | Локальный TUN-прокси рвёт TLS. Скрипт повторяет `gradlew` (по умолчанию 8 попыток, `--retries N` меняет) и переживает обрывы сам; повтор стоит почти ничего, артефакты Gradle кэшируются |
| `Cannot find a Java installation` при `JAVA_HOME = jbr` Android Studio | AGP требует именно 21, а Android Studio даёт 25. Это разные инструменты: `JAVA_HOME` — JVM, которой запускается Gradle, JDK 21 — тулчейн для компиляции. См. первый пункт |
| `assets/public/index.html` не появился после `cap sync` | Скрипт падает с явным сообщением, а не собирает «всё как получится»: сравниваются размеры `dist/index.html` и копии в `android/app/src/main/assets/public`. Не совпали — `cap sync` отработал не полностью |
| `release-сборка падает, потому что нечем подписать` | Нужен `android/keystore.properties` и `android/nexus-release.jks`. **Сам скрипт в этом случае честно падает** (он требует файл для release), а Gradle без него собрал бы неподписанный APK — так и задумано, чтобы `cap sync` и Android Studio не падали на чистой машине. Команда `keytool` для перевыпуска ключа записана в самом `keystore.properties` |
| Иконка приложения — зелёный робот Capacitor | Шаблон `npx cap add android` кладёт дефолтные `mipmap-*`. Заменить: `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-android-icons.ps1` (или `npm run build:apk -- --icons`) |
| `ArgumentOutOfRangeException` при конвертации иконки | Внутри `public/favicon.ico` лежит PNG, а `[System.Drawing.Icon]::ToBitmap()` на картинке 256×256 падает. Скрипт разбирает контейнер ICO вручную и грузит payload как `Bitmap` |

### 10.2 Что делает и чего не делает мост

Мост переписан под Capacitor 8 (`src/platform/android/capacitorBridge.ts`, 344 строки). Раньше 6 из 8 методов контракта работали молча и неверно — `onBackButton` (DOM-событие `backbutton` из соглашения Capacitor 2, которое современный контейнер не отправляет), `notify` (`Capacitor.Plugins.LocalNotifications`, удалённый в 3+), `saveTextFile` (`<a download>`, который в WebView файл не сохраняет, но функция возвращала `true`), `appVersion` (всегда `1.0.0`), `openDataFolder` (заглушка) и `storageHint` (несуществующий путь `sqlite://…`).

Симптомы, если мост откатится к старому виду:

| Симптом | Причина |
|---------|---------|
| Аппаратная «Назад» сразу выбрасывает из приложения | подписка на DOM-событие `backbutton` вместо `App.addListener("backButton", …)`; родной плагин отправляет событие только при наличии подписчика, иначе уходит в `webView.goBack()` |
| «Назад» срабатывает дважды | подписка и на DOM-событие, и на нативное: начиная с Capacitor 7 нативный код шлёт `backbutton` дополнительно |
| Уведомления не приходят, а настройки обещают поддержку | `features.notifications` вычисляется по наличию плагина; если оно жёстко `true`, а плагина в сборке нет — это ложь в интерфейсе |
| Экспорт в JSON «успешен», а файла нет | `<a download>` в WebView: у Capacitor нет `DownloadListener`, blob-URL игнорируется. Нужен `@capacitor/filesystem` |
| Экспорт падает с ошибкой Share | `Directory.Data` в `@capacitor/filesystem` + `@capacitor/share` не работает: в `res/xml/file_paths.xml` нет `files-path`, и `FileProvider` не отдаст такой файл. Отсюда порядок попыток `Directory.Documents` → `Directory.External`, а из папки приложения файл уходит через системное меню «Поделиться» |
| В настройках показано место хранения, которого нет | `storageHint()` должен возвращать `indexeddb://nexus-finance/db.sqlite (внутри приватного хранилища приложения)`. Файла `sqlite://…` на Android не существует |
| Кнопка «Открыть папку с данными» нажимается и ничего не делает | у WebView нет пользовательской папки. Пункт скрывается по `features.dataFolder !== false`; само поле необязательное, чтобы не ломать типы мостов, которые его не описывают |
| Подписка «назад» переподписывается на каждом рендере | инлайновые стрелки из `App.tsx` попадали в зависимости эффекта `usePlatformBackButton`. Актуальные обработчики надо держать в `ref`, подписку — один раз |

### 10.3 Подпись, публикация и чего APK не может

- **Установщик и APK не подписаны.** Для Windows нужен сертификат подписи кода (OV или EV) и цепочка доверия: `build.win.certificateFile` / `certificatePassword` либо `CSC_LINK` / `CSC_KEY_PASSWORD`, плюс `build.win.signtoolOptions` для метки времени. Пока сертификата нет, SmartScreen показывает «Неизвестный издатель», а свойство «Файл» в свойствах `.exe` помечает сборку как непроверенную.
- **Ключ Android самоподписанный** (RSA-4096, схемы v2 + v3; `enableV1Signing false`, потому что `minSdk 24`). Для ручной установки `.apk` этого достаточно. **Google Play его не примет** без загрузки ключа в Play App Signing, а для публикации нужен `AAB`, не `APK`.
- **`versionCode` поднимается вручную** в `android/app/build.gradle` (`versionCode 1`, `versionName "1.0.0"`); связи с полем `version` в `package.json` нет, автоматического инкремента нет.
- **APK запускался на устройстве — раньше только сверялся по составу пакета.** Первая
  проверка была невозможна: в среде нет образа системы и драйвера гипервизора,
  AVD не создавались, поэтому долгое время проверялись только идентификатор,
  версия, `minSdk`/`targetSdk`, метка, разрешения и совпадение веб-ассетов с
  `dist/`. Сейчас установлен подписанный release-APK на **Infinix X6858,
  Android 16 (SDK 36)**: запуск, база, кнопка «Назад», экспорт и настройки
  проверены, найденные дефекты — §10.5 и §10.6. **Требует проверки:** камера и
  распознавание чеков (нужен доступ к `cdn.jsdelivr.net`), альбомная ориентация,
  анимация predictive-back, отправка файла системным меню «Поделиться» и другие
  устройства. Эмулятор по-прежнему не используется.

### 10.4 Логи и главный риск

Окна консоли в APK не бывает: это Activity с `android.webkit.WebView`. Вывод рендерера попадает в `adb logcat` и **только в debug-сборке** — в release Chromium WebView сообщения консоли не выводит вообще. Спама не будет: `console.log` в коде ноль вызовов, все 21 вызов `console.*` стоят в `catch`, rAF-цикл чист. Порядок работы с `adb` — в `docs/Разработка.md` §3.

**Главный архитектурный риск — потеря базы, и рисков теперь два, а не один.**

1. **Очистка данных приложения.** IndexedDB в WebView стирается вместе с
   приложением; на Windows файл БД в `userData` очистку кэша переживает, на
   Android — нет.
2. **Бэкап ОС.** Раньше риска не было только потому, что он был *незамечен*:
   `allowBackup="true"` без правил отдавал приватное хранилище (IndexedDB с базой
   плюс дубль в `localStorage`) в Google Backup, и на другом устройстве база могла
   восстановиться молча — вместе с настройками и демо-данными чужого человека.
   Теперь запрещено: `allowBackup="false"`, а `res/xml/data_extraction_rules.xml`
   (Android 12+) и `res/xml/backup_rules.xml` (Android 11 и ниже) исключают и
   `cloud-backup`, и `device-transfer` — то есть перенос «телефон → телефон» тоже.

**Следствие, которое нельзя пропустить:** раз система больше не восстанавливает
базу, экспорт из Настроек — **единственная страховка, и он обязателен, а не
рекомендация**. Проверено на устройстве: пакета нет в списке бэкапа. Полностью
закрыть риск без участия пользователя можно только нативной файловой БД — это
отдельная задача, а не строчка конфигурации.

## 11. Диагностика по журналу

**Где лежит.** `%APPDATA%\nexus-finance\logs\nexus-finance.log` — путь из `app.getPath('logs')`, при старте пишется строкой `[main] файл журнала: <путь>`. В собранном приложении имя папки берётся из `build.productName` — то есть `NEXUS Finance`; `npm run verify:db` ищет оба варианта плюс `Electron`. Ротация: один предыдущий файл, лимит 2 МБ (`LOG_LIMIT`); проверка размера идёт **только при открытии файла**, то есть при старте, — за долгую сессию журнал может вырасти больше 2 МБ.

| Префикс | Что означает |
|---------|--------------|
| `[main]` | версии Electron/Node/Chromium, путь к базе, «рендерер загружен», «значок в трее создан» |
| `[main] !` | нет `public/favicon.ico`, навигация наружу запрещена, `window.open()` заблокирован, уведомления не поддерживаются, рендерер не отвечает, второй экземпляр закрыт |
| `[main] !!` | `dist/index.html` не найден, не удалось прочитать/сохранить/удалить файл базы, `preload не выполнился`, `страница не загрузилась`, `процесс рендерера завершился`, `запуск не удался` |
| `[renderer]` | `console.*` из интерфейса; в собранном приложении попадает и в файл журнала, иначе причина сбоя осталась бы нигде |
| `[preload]` | одна строка: `window.electronAPI готов (sandbox: true, contextIsolation: true)` |

Каждая строка файла начинается с метки времени `[ГГГГ-ММ-ДД ЧЧ:ММ:СС]`.

**Вывод в терминал.** `npm run electron:debug` = `electron . --dev`. Даёт дублирование лога рендерера с меткой `[renderer]` (обработчик `console-message`, `electron-main.cjs` строки 425–447 — он разбирает обе подписи события, потому что она менялась между версиями Electron, и пишет каждое сообщение **и** в консоль, **и** в файл журнала), открытие инспектора и весь вывод main. В собранном приложении окна консоли нет (§3.5), поэтому единственный источник — файл журнала.

**Диагностические каналы IPC.**

| Канал | Смысл `null` | Смысл ошибки |
|-------|--------------|--------------|
| `load-db` | файла базы нет (первый запуск) | файл есть, но не читается → **исключение**, не `null` |
| `pick-text-file` | пользователь отменил выбор | файл не читается → **исключение** |
| `save-db`, `save-text-file`, `notify`, `set-tray`, `open-data-folder` | — | `false` + причина в лог |

Различать `null` и исключение здесь не стилистическое требование: иначе `ElectronSnapshotStore` решит, что данных нет, и автосохранение затрёт файл (комментарий к `load-db` и к `SqliteStorage.open()`).

## 13. Чего делать нельзя

| Запрет | Почему |
|--------|--------|
| **Не отключать очередь операций** в `SqliteStorage.enqueue()` | SQLite допускает только одну активную транзакцию. Без очереди два автосохранения подряд попадут в одну незавершённую транзакцию: чужой `ROLLBACK` откатит уже возвращённый вызову `true` результат, а удаление устаревших строк снесёт только что записанные данные. `write()` обязан идти через ту же очередь, что и `transaction()` |
| **Не возвращать `null` из `load-db` при ошибке чтения** | `null` для рендерера означает «базы нет», и первое же автосохранение записало бы пустую базу поверх существующего файла. `null` — только когда файла нет; при ошибке бросаем исключение (`electron-main.cjs`, строки 138–151) |
| **Не выставлять `ipcRenderer` наружу из preload** | `contextIsolation: true` и `sandbox: true`. Наружу отдаётся только `window.electronAPI` — набор функций; модули и внутренние переменные в мире страницы быть не должны |
| **Не добавлять node-модули в `rollupOptions.external`** | В бандл попадёт голый `import "fs"`, и страница упадёт с `Failed to resolve module specifier "fs"`; в dev это скрыто заглушками Vite. Ловится `npm run verify:dist` |
| **Не править `clip-path` в расчёте на рамку** | `clip-path` срезает рамку по диагоналям — фигура выглядит обрубленной. Контур рисуется `box-shadow: inset`: он обрезается тем же `clip-path` и идёт ровно по контуру. В `.hex` толщина и цвет задаются один раз (`--hex-ring`, `--hex-ring-color`), в разметке остаётся только цвет и заливка — иначе поверх inset-тени ляжет вторая тонкая линия |
| **Не указывать проценты больше 100% в `color-mix()`** | Значения вроде `color-mix(in srgb, var(--accent) 140%, transparent)` некорректны и ломают цвет; доли в `src/index.css` в сумме дают 100% |
| **Не вызывать `db.export()` внутри транзакции** | Экспорт закрывает и пересобирает образ БД, транзакция пропадает, и `COMMIT` падает с `cannot commit - no transaction is active`. Снапшот пишется только после `COMMIT` |
| **Не проглатывать ошибку записи снапшота** | Данные в памяти есть, на диск не попали. Ошибка намеренно пробрасывается наверх — иначе пользователь увидит «сохранено» |
| **Не оставлять процесс без окон и без трея** | Он держит `single-instance lock` невидимо, и следующий запуск завершится молча. В коде для этого есть явная проверка с `app.quit()` |
| **Не убирать `cdn.jsdelivr.net` из `script-src`** | Воркер `tesseract.js` создаётся из `blob:`-URL и тянет свой скрипт через `importScripts`, который проверяется по `script-src` унаследованной политики. Уберут — распознавание чеков перестанет работать и в Electron, и на Android, причём без внятной ошибки. В `connect-src` хост нужен отдельно: оттуда воркер грузит wasm-ядро и языковые данные |
| **Не убирать зеркало Maven Central из `android/settings.gradle` и `android/build.gradle`** | В этой сети `repo.maven.apache.org` и `repo1.maven.org` за локальным TUN (198.18.x.x) и рвут TLS; без зеркала Gradle не резолвит `kotlin-stdlib` и Cordova-зависимости. `npx cap update` перегенерирует `capacitor.settings.gradle`, но эти два файла не трогает — проверяйте после обновления Capacitor |
| **Не переносить `pluginManagement` вниз `settings.gradle`** | Gradle 9.3.1 требует, чтобы он был первым оператором файла, иначе `must appear before any other statements` |
| **Не ставить `disableBackButtonHandler: true`** в `capacitor.config.ts` | Тогда нативный плагин не создаст `OnBackPressedCallback` вовсе, кнопка «Назад» перестанет доходить до JS, а вместе с ней — логика закрытия модалки и возврата на главный экран |
| **Не заводить вторую подписку на `backButton`** | Capacitor раздаёт одно нативное событие **всем** подписчикам (`@capacitor/core`, `notifyListeners: listeners.forEach`), а мост после вызова смотрит на результат: вернувший `false` зовёт `passBackToSystem(event.canGoBack)` — либо `history.back()`, либо `App.exitApp()`. Вторая подписка превратит «закрыть шторку» в «закрыть шторку и выйти из приложения». Нативная подписка одна — в `installBackRouter()` (`AppShell.tsx`), остальные слои кладут обработчики в слоты `backRouter` |
| **Не возвращать `allowBackup="true"`** в `AndroidManifest.xml` | Приватное хранилище (запись IndexedDB с базой плюс дубль в `localStorage`, `src/storage/snapshots.ts`) целиком уходит в Google Backup и может восстановиться на другом устройстве молча. `allowBackup="false"` плюс `res/xml/{data_extraction_rules,backup_rules}.xml` закрывают и облачную копию, и перенос «телефон → телефон». Побочный эффект: **экспорт в JSON стал обязательным** — восстановить базу больше нечем |
| **Не возвращать `formatNumber` к `style: "currency"`** | `Intl.NumberFormat` со `style: "currency"` подставляет знак валюты сам, и подменить его после нельзя. В системном шрифте телефона (Infinix X6858, Android 16) нет глифа ₽ (U+20BD) — суммы рисуются как `557 885 ▯`. Форматируйте число отдельно и дописывайте знак из `readSymbol()`, который проверяет наличие глифа измерением ширины в канвасе |
| **Не убирать `--sat/--sar/--sab/--sal`** из `:root` | При `targetSdk 35+` приложение рисуется под системными панелями, и липкая шапка уезжает под строку состояния и вырез. Переменные читают `env(safe-area-inset-*)` с фолбэком на `0px` — на десктопе и в старых WebView они равны нулю, так что правка безопасна |
| **Не переносить правки касательного ввода за пределы `@media (pointer: coarse)`** | Зоны нажатия 44 px и кегль полей от 16 px нужны пальцу; на десктопе мыши они съедают место и ломают сетку. В `index.css` это отдельный блок, а не правка общих правил |
| **Не включать `minifyEnabled` без регрессии на устройстве** | Экономия 1–1,5 МБ, но неправильные keep-правила ломают вызовы нативных мостов (`@capacitor/*`), а ломаются молча. Это отдельная задача с полной регрессией, а не оптимизация по умолчанию |
| **Не убирать `public/**/*` из `files` в секции `build`** | Главный процесс читает `public/favicon.ico` для иконки окна и трея. Без него сборка пройдёт успешно, а иконок не будет — худший вид поломки |
| **Не возвращать `directories.app`** в секции `build` | Приложение сложится в подкаталог, и вход в asar станет другим; `electron-main.cjs` его не найдёт |
| **Не убирать `build.publish`** из `package.json` | Без него electron-builder не знает, куда публиковать, и `electron-updater` в приложении не знает, откуда читать обновления. Значения — приватный `dev-aitechpro/nexus-finance-beta`, `releaseType: "prerelease"`, `channel: "beta"` |
| **Не выкладывать в релиз метаданные канала под одним-единственным именем** | electron-builder пишет метаданные в файл, названный по `build.publish.channel` — при `channel: "beta"` это `beta.yml`. Но `PrivateGitHubProvider` (приватный репозиторий, а он у нас приватный) ищет **всегда** `latest.yml`: он берёт `getDefaultChannelName()` и настройку `channel` не учитывает. `scripts/publish-release.mjs` поэтому кладёт одни и те же метаданные в релиз под обоими именами — `beta.yml` и `latest.yml` |
| **Не публиковать релиз обычным, а не prerelease** | Релиз с тегом `v1.0.0-beta.1` без метки «предварительный» не попадёт в выборку `electron-updater` при `allowPrerelease` и не будет виден как «последняя версия» в списке релизов |
| **Не вставлять токен в аргументы скрипта** | `GITHUB_TOKEN` — только переменная окружения. Аргумент командной строки виден в списке процессов и в истории оболочки, и скрипт не примет токен оттуда намеренно |
| **Не оставлять токен в `.git/config`** | `git remote add origin https://<токен>@github.com/…` сохраняет токен в конфиге навсегда и отдаёт его всем, кто читает репозиторий. `scripts/publish-release.mjs` передаёт его git через `GIT_CONFIG_COUNT`/`GIT_CONFIG_KEY_0`/`GIT_CONFIG_VALUE_0` — только на время команды |

## 14. Публикация и обновления

Раздел относится к `scripts/publish-release.mjs` (создаёт приватный репозиторий `dev-aitechpro/nexus-finance-beta`, тег, prerelease-релиз и загружает файлы) и к тому, что после этого происходит в установленном приложении. Полный порядок подготовки релиза — [Разработка.md](Разработка.md) §13.

### 14.0 С этой машины GitHub недоступен

Симптом: `curl.exe -I https://github.com` отвечает `200 OK`, но `curl.exe -I https://api.github.com` не отвечает, `git ls-remote https://github.com/dev-aitechpro/nexus-finance-beta` обрывается на TLS, и скрипт публикации падает сразу на первом запросе.

Причина: маршрута до GitHub с этой машины нет — токен у пользователя есть, а сети до `api.github.com` и до `github.com` по TLS нет. Это не проблема скрипта, токена или репозитория. Проверено: корень `github.com` отвечает, `info/refs?service=git-upload-pack` и REST API — нет. Тот же блокер описан в §9 и в `docs/Разработка.md` §12 для других хостов.

Решение: запускать публикацию из сети, где GitHub доступен (другая машина, домашняя сеть без локального TUN-прокси, мобильный хотспот). Последовательность та же:

```powershell
$env:GITHUB_TOKEN = "github_pat_…"; node scripts/publish-release.mjs
```

Проверка перед запуском, без публикации:

```powershell
curl.exe -I https://api.github.com          # ожидается 200 OK
git ls-remote https://github.com/dev-aitechpro/nexus-finance-beta
```

Если `api.github.com` отвечает `200`, сеть годится. Если нет — публикация невозможна ни при каком токене, и скрипт сам скажет об этом на шаге «проверка GITHUB_TOKEN».

### 14.1 Публикация не идёт: токен, права, репозиторий

| Симптом | Причина | Решение |
|---------|---------|---------|
| `Не найден GITHUB_TOKEN — публикация невозможна` | Переменная не выставлена в этом окне терминала | `$env:GITHUB_TOKEN = "github_pat_…"` в том же окне, где запускается скрипт. Скорость смены токена не нужна: у скрипта есть время, а внести его в `.env` нельзя — `.env` попадает в сборку через `files` и уехал бы в релиз |
| `401 Bad credentials` | Токен истёк, отозван или скопирован с пробелом | Выпустить новый в Settings → Developer settings → Personal access tokens. Пробел по краям скрипт режет сам, но пробел внутри — нет |
| `403` при создании репозитория, `Resource not accessible by integration` | У classic PAT нет scope `repo`, у fine-grained — нет прав Administration на аккаунт | Классический токен: scope `repo`. Fine-grained: Repository access → нужный репозиторий, Repository permissions → Contents: Read and write, для создания репозитория — Administration: Read and write. Либо создать репозиторий вручную (Settings repositories → New, **Private**) и запустить скрипт снова: он увидит готовое и продолжит |
| `404` на `GET /repos/dev-aitechpro/nexus-finance-beta` | Репозитория нет, и токен его не видит | Скрипт сам создаст его через `POST /user/repos` с `private: true`. Если `404` при этом остаётся — у токена нет прав на создание репозиториев, см. предыдущую строку |
| `422` при `POST /releases` | Тег уже есть, но релиз с ним не связан, либо релиз с таким именем уже создан | Проверить `GET /repos/dev-aitechpro/nexus-finance-beta/releases` и удалить прошлый через `DELETE /repos/dev-aitechpro/nexus-finance-beta/releases/<id>`. Скрипт умеет переиспользовать существующий релиз; `422` значит, что состояние нестандартное и нужно посмотреть глазами |
| `407` или зависание при загрузке файла | Корпоративный прокси перехватывает `uploads.github.com` | Загрузка идёт на отдельный хост, не на `api.github.com`: сначала API, потом `uploads.github.com`. Если прокси блокирует загрузку, настраивают `NO_PROXY=uploads.github.com,api.github.com` |
| `507` при загрузке | Исчерпана квота хранилища аккаунта | На бесплатном тарифе квота Releases — 2 ГБ суммарно. При превышении удалите старые релизы: файлы исчезнут оттуда сразу |
| Загрузка `.exe` на 100 МБ обрывается на середине | Прокси или антивирус режет длинное соединение, а не GitHub | Лимит на один файл — 2 ГБ, так что дело не в размере. Попробуйте другую сеть либо разбейте загрузку: соберите portable-версию отдельно (`node scripts/build-windows.mjs --nsis-only` оставляет только установщик) и выложите релизы по очереди |
| Репозиторий создан, но оказался публичным | `private` не применился (создан вручную с галочкой «Public») | **Закрыть немедленно**: Settings → Danger zone → Change visibility → Private. Скрипт на это указывает при следующем запуске и останавливается, пока репозиторий публичный |

| Повторный запуск не перезаливает файл | Скрипт по умолчанию не трогает уже загруженное — это и есть идемпотентность | `--force-assets` удалит прежний файл и загрузит заново |

### 14.3 Приложение не находит обновление

Самая частая причина — не «сломалась сеть», а рассинхрон между тем, куда публикуют, и тем, откуда читает приложение. Сверять три вещи: `build.publish` в `package.json`, `scripts/publish-release.mjs` (тот же репозиторий) и код автообновления в `src/**`.

| Симптом | Причина | Решение |
|---------|---------|---------|
| `ERR_UPDATER_CHANNEL_FILE_NOT_FOUND` / `Cannot find latest.yml in the latest release artifacts` | Репозиторий приватный, поэтому работает `PrivateGitHubProvider`, а он ищет **всегда** `latest.yml`, игнорируя `channel: "beta"`. В релиз попал только `beta.yml` | Положить метаданные под обоими именами — так и делает `scripts/publish-release.mjs`. Если файлы выкладывали вручную — продублировать `latest.yml` |
| `Update for version 1.0.0-beta.1 not found` | В релизе нет метаданных канала вовсе, либо в них версия от прошлой сборки | `beta.yml` (и `latest.yml`) обязательны наравне с установщиком. Скрипт проверяет, что версия в метаданных совпадает с `package.json`, и останавливается на расхождении |
| `401`/`403` при проверке обновления | Приложение читает **приватный** репозиторий без авторизации | У приватного провайдера токен обязателен: `providerFactory` выбирает `PrivateGitHubProvider` по `process.env.GH_TOKEN`/`GITHUB_TOKEN` при `private: true`, иначе — обычный `GitHubProvider`, который к приватному репозиторию не имеет доступа. Токен в приложении — компромисс: лучше узкий токен, чем публичный репозиторий с исходниками |
| Обновление предлагается, но указывает на старую версию | В релизе лежат метаданные от прошлой сборки | Пересобрать и выпустить новую версию. Файл метаданных перезаписывается на каждой сборке, в релиз его кладут заново |
| `application is not packaged` | Проверка обновлений вызвана в dev-режиме (`npm run electron` / `electron .` из исходников) | Проверять на собранном приложении из `dist-electron`, а не на dev-сборке |
| Windows: «Модуль обновления не загрузился: Cannot find module 'electron-updater'» | В `app.asar` нет `node_modules`: сборка исключала его целиком (`"!**/node_modules/**/*"` в `build.files`), а главному процессу модуль нужен | В `build.files` перечислены обновлятель и его транзитивное замыкание — 16 пакетов, 2,2 МБ. Список не оставлен на память: `npm run verify:updater` сверяет его с реальным составом зависимостей и останавливает сборку при расхождении |
| Приложение нашло `1.0.0-beta.2`, хотя стояло `1.0.0-beta.1` — и это нормально | `electron-updater` сравнивает semver: `1.0.0-beta.1` < `1.0.0-beta.2` | Ожидаемое поведение для пре-релизов. Неожиданным будет обратное — предложение «обновиться» на ту же версию |
| Android: «проверка недоступна», хотя релиз есть | Проверка идёт через `https://api.github.com/repos/…/releases?per_page=5`. Важно: **не** `/releases/latest` — GitHub считает последним только полноценный выпуск и предварительные не возвращает, а все наши релизы помечены `prerelease`. Запрос к `latest` отвечал бы 404 всегда, и приложение вводило бы в заблуждение сообщением «нет доступа к закрытому репозиторию» | Список релизов, черновики отфильтрованы, выбор по дате публикации — так и сделано в `pickLatestRelease` (`src/lib/updater.ts`), покрыто `tests/updater.test.ts` |
| Android: `beta.10` считается старше `beta.9` | Пре-суффиксы сравнивались строками, где `"1" < "9"` | Сравнение по идентификаторам SemVer, числа сравниваются числами — `isNewerVersion` в `src/lib/updater.ts`. Иначе на десятой бете приложение сообщало бы пользователю, что у него более свежая сборка |
| Android: `TypeError` без кода при нажатии «Проверить» | Запрос заблокирован политикой безопасности сборки: в `connect-src` не было `api.github.com` | Хост добавлен в `vite.config.ts`. Там же объяснено, что на Windows проверку делает главный процесс, который CSP не касается |
| Android: обновление предлагается, но установить нельзя | **Это не дефект.** `electron-updater` работает только в Electron; APK не может заменить себя | Приложение прямо пишет об этом и открывает страницу релиза в системном браузере. Установка — вручную новым `app-release.apk` поверх старого |

### 14.4 Приложение не подписано, автообновление не работает

Подпись влияет не на саму механику обновления, а на доверие к ней: SmartScreen
и Android показывают предупреждение о неизвестном издателе. Проверить, что
подпись действительно была проверена, `electron-updater` в нашем случае
не может — сертификата нет, а его обработчик при недоступной проверке
возвращает «проверка не выполнялась» без ошибки. Поэтому приложение **никогда**
не пишет «подпись проверена»: в настройках висит постоянное предупреждение.

| Симптом | Причина | Решение |
|---------|---------|---------|
| Windows: «Неизвестный издатель», SmartScreen ругается | Установщик не подписан сертификатом. В `build.win` нет ни `certificateFile`, ни `CSC_LINK` | Это **не блокирует** `electron-updater`: подпись влияет на предупреждение SmartScreen, а не на механику обновления. Для приватной беты оставить как есть; для публичного релиза понадобится сертификат OV/EV, `build.win.certificateFile` + `certificatePassword` либо `CSC_LINK`/`CSC_KEY_PASSWORD` плюс `signtoolOptions` для метки времени |
| Windows: после обновления приложение не запускается | Установка поверх ранее установленной версии с другим `appId` или без `nsis` в `build.win.target` | `appId` (`com.nexus.finance`) и `productName` нельзя менять между версиями: смена `appId` ставит вторую копию рядом, а не обновляет старую |
| Android: `INSTALL_FAILED_UPDATE_INCOMPATIBLE` | Подпись нового APK не совпадает с подписью установленного | Ключ из `android/keystore.properties` потерян или заменён. Восстановить тот же ключ — иначе старую версию придётся удалять с устройства руками, а данные приложения удалятся вместе с ней (см. §10.4 про экспорт) |
| Android: `INSTALL_FAILED_VERSION_DOWNGRADE` | `versionCode` в `android/app/build.gradle` не поднят или ниже установленного | Поднять `versionCode` целым числом, строго большим предыдущего. Связь с `version` в `package.json` автоматическая, её нет |
| Google Play: загрузка отклонена | Нужен `AAB`, а не `APK`, плюс ключ, принятый Play App Signing | Для Play нужен отдельный релизный цикл; в проекте публикация идёт через `scripts/publish-release.mjs` в GitHub Releases, и APK с самоподписанным ключом в Google Play не попадёт |
| Обновление скачивается, но распаковка падает | Повреждённая загрузка или несовпадение `sha512` в метаданных канала | Проверить, что в релиз загружены `.exe` и метаданные **из одной сборки**. Смешанные файлы из `dist-electron` разных прогонов — типичная причина |

### 14.5 Скрипт публикации: частые сообщения и что за ними

| Сообщение | Что означает | Что делать |
|-----------|--------------|------------|
| `версии разошлись: package.json …, android/app/build.gradle …` | `version` и `versionName` не совпадают | Поднять версию в обоих местах (§13.2 в [Разработка.md](Разработка.md)) |
| `рабочее дерево не чистое` | Есть незакоммиченные изменения | `git add -A && git commit` и запустить снова, либо `--allow-dirty`, если публикуется именно текущий коммит |
| `тег v1.0.0-beta.1 уже есть и указывает на другой коммит` | Номер версии уже использовали | Поднять версию: `1.0.0-beta.1` → `1.0.0-beta.2` в трёх местах и повторить |
| `репозиторий не создан` / `403` при `POST /user/repos` | Не хватает прав на создание | Выпустить токен с Administration: Read and write либо создать приватный репозиторий вручную |
| `git push origin … rejected` | Ветка или тег на сервере уже есть и указывают на другое | Обычно лечится `--allow-dirty` плюс `git push --force-with-lease origin main`; для тега — удалить тег на сервере и создать заново |
| `GitHub API: 404` на загрузке файла | Релиз удалён между созданием и загрузкой | Запустить скрипт заново: он переиспользует существующие сущности и дозагрузит файлы |
| Всё прошло, а в `releases.atom` нет нового тега | GitHub обновляет Atom-фид с задержкой в несколько секунд | Подождать и обновить страницу. На приватный репозиторий анонимный Atom-фид не отдаётся вовсе — это ожидаемо, доступ к фиду даёт `electron-updater` с авторизацией |
