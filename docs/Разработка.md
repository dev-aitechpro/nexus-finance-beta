## 2. Требования к машине

| Что | Версия | Почему |
|-----|--------|--------|
| Node.js | **22.18+ или 24** | `scripts/bench-storage.mjs` использует `module.registerHooks` (Node ≥ 22.15) и перезапуск с `--experimental-transform-types`; `scripts/check-desktop-db.mjs` и `scripts/generate-project-map.mjs` импортируют `.ts` напрямую (в их шапках: «Node 22.18+/24», «Node 23+») |
| npm | 11.x | Проверено на 11.19.0 |
| ОС | Windows — для установщика и APK; Linux/macOS — для тестов и веб-сборки | `build.win.target = nsis`, `arch: ["x64"]` в `package.json`; конвертер иконок Android написан под `System.Drawing` |
| Electron-бинарь | 43.x | Лежит в `node_modules/electron/dist` + `node_modules/electron/path.txt` |
| Android SDK | platforms 35/36/37, build-tools 36 | Только для `build:apk`. Ищется через `ANDROID_HOME` / `ANDROID_SDK_ROOT`, `android/local.properties` или стандартный каталог |
| **JDK 21** | 21 | **Обязателен для `build:apk`:** Android Gradle Plugin берёт компилятор из тулчейна с `languageVersion = 21`, иначе `ToolchainProvisioningException`. В системе бывает только JDK 25 — тогда положите JDK 21 в `%USERPROFILE%\.gradle\jdks\` или укажите `NEXUS_JDK21` |
| JDK для самого Gradle | 21 или новее | Gradle 9.3.1 как JVM требует Java 21+; берётся из `JAVA_HOME`, Android Studio `jbr` или `java` в `PATH` |

Проверенная конфигурация: **Node 24.21.0, npm 11.19.0, Electron 43.7.5 (Node 24.21.0 / Chromium 150), sql.js 1.13.0, Gradle 9.3.1, Android Gradle Plugin 8.13.1**.

**Дополнительно для сборки установщика.** `npm run build:win` (`scripts/build-windows.mjs`) — это `build` + `electron-builder`, которому нужна сеть: он скачивает NSIS и `winCodeSign`. Скрипт сам ставит зеркало бинарей `ELECTRON_BUILDER_BINARIES_MIRROR` (переопределяется переменной окружения) и повторяет шаг electron-builder до четырёх раз, потому что соединение рвётся на первой TLS-сессии. Electron берётся локально установленный (`build.electronDist`), а не качается заново. Артефакты и их состав — в `README.md` и `docs/Выполнение-ТЗ.md` §7б.

**Дополнительно для сборки APK.** `npm run build:apk` (`scripts/build-android.mjs`) находит SDK и JDK сам, ищет JDK 21 и передаёт его Gradle через `-Porg.gradle.java.installations.paths`, синхронизирует веб-ассеты (`npx cap sync android`) и повторяет `gradlew` при обрывах TLS. **Зеркало Maven Central в `settings.gradle` и `build.gradle` не удалять** — без него сборка падает: `repo.maven.apache.org` в этой среде живёт за локальным TUN и рвёт рукопожатие. `pluginManagement` обязан остаться первым оператором `settings.gradle` — иначе Gradle 9.3.1 откажется работать.

**Если не скачался бинарь Electron** (пакет ставился с `ELECTRON_SKIP_BINARY_DOWNLOAD` или зеркала недоступны):

1. Проверить: `node_modules/electron/path.txt` и `node_modules/electron/dist/electron.exe` на месте.
2. Скачать архив версии 43.7.5 из доступного зеркала. В сети проекта рабочим оказалось `mirrors.huaweicloud.com/electron` — 144 МБ, распаковано 360 МБ; `github.com` и зеркала Tsinghua/NJU отдавали `ECONNRESET`.
3. Распаковать в `node_modules/electron/dist`, записать в `path.txt` строку `electron.exe`.
4. `npm run electron:debug` — должно открыться окно, а в терминале появиться `[preload] window.electronAPI готов`.

## 3. Установка и запуск

```bash
npm install
```

**Браузерный режим.** `npm run dev` = `vite --open --config vite.dev.config.ts`. Dev-конфиг отличается от продового только входом: `build.rollupOptions.input` → `index.dev.html` → `src/main.dev.tsx`, который дополнительно рендерит `<DevTools />`; прод-вход `index.html` → `src/main.tsx` без него. В обоих конфигах выход — один файл (`vite-plugin-singlefile`), WASM встраивается как base64 (плагин `?wasm-inline` из `vite.shared.ts`).

`DevTools` (`src/components/DevTools.tsx`) включается ключом `VITE_DEV_ACCESS_KEY` из `.env`. Переменных `.env` в репозитории нет, а сам файл в `.gitignore` — то есть без локального `.env` панель не рендерится **вообще**, в том числе в `src/App.tsx`, где `<DevTools />` подключён безусловно.

**Режим Electron.** Electron грузит `dist/index.html` по `file://`, поэтому сначала обязателен `npm run build`. Дальше:

```bash
npm run electron:debug   # electron . --dev — инспектор + лог рендерера в терминал
npm run electron         # electron . — прод-оболочка, без инспектора
npm run dev:desktop      # build + electron:debug, одной командой
```

Без флага инспектор не открывается никогда: `DEBUG` в `electron-main.cjs` включается только `--dev` или переменной `NEXUS_DEVTOOLS=1`.

**Отладка.** `electron-main.cjs` дублирует в терминал `console.*` рендерера (обработчик `console-message`), а также ошибки загрузки страницы, `preload-error` и падение процесса рендерера. Те же сообщения идут в файл журнала через общий сток — в собранном приложении окна консоли нет (electron.exe — GUI-сборка), поэтому всё важное пишется в `app.getPath('logs')/nexus-finance.log`; в установленном приложении это единственное место, где видно причину сбоя при старте.

**Режим Android.** Gradle-проект лежит в `android/`, конфигурация — в `capacitor.config.ts`. Рендерер грузится с `https://localhost` (схема `https` даёт secure context, нужный для камеры и IndexedDB), веб-ассеты кладутся в `android/app/src/main/assets/public` командой `npx cap sync android`. Сборка:

```bash
npm run build:apk          # release → android/app/build/outputs/apk/release/app-release.apk
npm run build:apk:debug    # debug   → android/app/build/outputs/apk/debug/app-debug.apk
```

Полезные ключи скрипта: `--icons` (перегенерировать `mipmap-*` из `public/favicon.ico`),
`--no-sync` (не запускать `npx cap sync android`), `--retries 12`, `--clean`,
`--with-web` (сначала `npm run build`). В `capacitor.config.ts` **нельзя** ставить
`App.disableBackButtonHandler: true`: нативный плагин тогда вообще не создаёт
обработчик аппаратной «Назад», и логика из `src/hooks/usePlatformBackButton.ts`
перестаёт работать. Подпись release читается из `android/keystore.properties`
(в `.gitignore`); файла нет — release соберётся неподписанным.

### Проверка на реальном устройстве

Всё, что ниже, нужно на живом телефоне с включённой отладкой по USB
(«Для разработчиков» → «Отладка по USB»). Эмулятор в этой среде недоступен: нет
образа системы и драйвера гипервизора, AVD не создавались. Первая такая проверка
прошла на Infinix X6858, Android 16 (SDK 36).

**Полезные команды (PowerShell, каталог проекта).** Почти все только читают
состояние устройства; исключения — `install` (ставит пакет) и `am start`
(запускает Activity). Для обычной сборки ничего из этого не нужно.

```powershell
adb devices                                    # телефон виден? колонка device, не unauthorized
adb install -r android\app\build\outputs\apk\release\app-release.apk
adb shell am start -n com.nexus.finance/.MainActivity
adb shell dumpsys window | findstr mCurrentFocus    # что сейчас на экране
adb shell dumpsys package com.nexus.finance | findstr versionName
adb shell wm size; adb shell wm density       # ширина в CSS-пикселях = wm size / (wm density / 160)
adb shell input tap 540 1200                   # нажатие
adb shell input swipe 540 1600 540 400 300     # прокрутка
adb shell input keyevent 4                     # аппаратная «Назад»
adb logcat | findstr /i "chromium nexus"      # сообщения рендерера — только в debug-сборке
adb shell bmgr list-backup-preds | findstr nexus   # пакета быть не должно: бэкап запрещён
```

**Ширина в CSS-пикселях — считайте, а не угадывайте.** `wm size` и `wm density`
дают физические пиксели и плотность, а вёрстка считает в CSS-пикселях:
`1080 / (440 / 160) ≈ 393`. Именно на этой ширине девять пунктов навигации не
помещались, поэтому проверять «у меня ширина побольше» нельзя: имеет значение
реальная ширина в CSS-пикселях, а не модель телефона.

**Координаты — из `uiautomator dump`, а не на глаз.**

```powershell
adb shell uiautomator dump /sdcard/ui.xml
adb pull /sdcard/ui.xml .
Select-String -Path ui.xml -Pattern 'Ещё|Настройки'   # атрибут bounds="[x1,y1][x2,y2]"
```

Дальше `adb shell input tap <центр bounds>`. Ручной подсчёт по скриншоту работает,
но промахивается — у `uiautomator` есть и `resource-id`, и `text`, и `content-desc`
(то есть по `content-desc` находится иконка без подписи).

**Скриншот — только через `cmd /c`.** Наивная запись
`adb exec-out screencap -p > screen.png` в PowerShell даёт **испорченный файл**:
PowerShell перенаправляет вывод команд как текст, переводя `\r\n` в `\n` и
порча байты PNG, которые невалидны. Рабочий вариант — отдать перенаправление
`cmd.exe`, где двоичный вывод не трогается:

```powershell
cmd /c "adb exec-out screencap -p > screen.png"
```

Альтернатива без всякого перенаправления: `adb shell screencap -p /sdcard/s.png`
и затем `adb pull /sdcard/s.png .` — файл качается целиком, искажений быть не может.
Способ через `pull` медленнее, но предсказуем, если первый вдруг даст «битый» PNG.

**Что обязательно проверять руками на телефоне.** Ни один из этих пунктов не
ловится автотестами и не виден в десктопном браузере:

- клавиатура в модалке не гаснет сразу после открытия (фокус должен встать в
  **поле**, а не в крестик — на `pointer: coarse` задержка 260 мс);
- аппаратная «Назад» проходит всю цепочку: верхний диалог → модалка транзакции →
  возврат на «Обзор» → выход из приложения;
- нижняя лента: пять пунктов помещаются, «Ещё» открывает все девять разделов, текущий
  помечен галочкой;
- всплывающее сообщение не закрывает ленту вкладок;
- липкая шапка не уезжает под строку состояния и под вырез;
- знак валюты — не «плашка» (см. `readSymbol`, `docs/Архитектура.md` §5.3);
- экспорт в JSON: файл реально появляется в публичной папке «Документы» и открывается.

**Требует проверки** (на устройстве не проверено): камера и распознавание чеков
(нужен доступ к `cdn.jsdelivr.net`), альбомная ориентация, анимация
predictive-back, отправка файла системным меню «Поделиться» (в том числе
открывается ли файл из публичной папки) и несколько разных устройств.

**Осторожно с `adb shell pm clear com.nexus.finance`** — команда стирает все
данные приложения вместе с базой, и восстановить их будет нечем: экспорт
обязателен, бэкап ОС запрещён (`docs/Решение-проблем.md` §10.4). Перед ней
сделайте экспорт в JSON.

## 4. Скрипты npm

Все команды — из `package.json`, секция `scripts`.

| Команда | Что делает | Когда нужна |
|---------|-----------|-------------|
| `npm run dev` | Dev-сервер Vite с dev-конфигом | Разработка интерфейса |
| `npm run build` | `vite build` → `dist/index.html` (один файл, ~2.9 МБ) | Перед запуском Electron и перед сдачей |
| `npm run build:electron` | `build` + `electron-builder` → `dist-electron` (NSIS x64) | Только релиз; нужна сеть |
| `npm run build:win` | `scripts/build-windows.mjs`: `build` + `electron-builder --win --x64` с целями `nsis` и `portable`, зеркалом бинарей и четырьмя попытками. **Релизная сборка Windows** | Только релиз; нужна сеть |
| `npm run build:apk` | `scripts/build-android.mjs --release`: поиск SDK/JDK/JDK 21, `cap sync android`, `gradlew :app:assembleRelease` | Релизный APK; нужны SDK и JDK 21 |
| `npm run build:apk:debug` | То же для debug: `app-debug.apk` | Отладка на устройстве |
| `npm run electron` | `electron .` — прод-оболочка, без инспектора | Проверка «как у пользователя» |
| `npm run electron:debug` | `electron . --dev` — инспектор, лог рендерера | Отладка рендерера и IPC |
| `npm run dev:desktop` | `build` + `electron:debug` | Тот же десктопный цикл одной командой |
| `npm test` | `vitest run` — 84 теста в 3 файлах | Каждое изменение |
| `npm run test:watch` | `vitest` в watch-режиме | Локальная разработка тестов |
| `npm run coverage` | Тесты + отчёт в `coverage/` (html) | Перед рефакторингом слоя хранения |
| `npm run typecheck` | `tsc --noEmit` | После правок типов и контрактов |
| `npm run map` | Пересборка `project-map.json` | После добавления/переименования модулей |
| `npm run verify:dist` | `scripts/check-dist.mjs`: артефакт есть, нет голых импортов node-модулей, js/css встроены, `<title>` на месте, локальные файлы существуют | Входит в `verify` |
| `npm run verify:file` | `scripts/check-file-protocol.mjs`: бандл безопасен под `file://` | Правки сборки, CSP, `base`, новые зависимости с ассетами |
| `npm run verify:db` | `scripts/check-desktop-db.mjs`: файл БД в профиле читается, сигнатура SQLite, `PRAGMA quick_check`, схема и все таблицы на месте | После запуска Electron, если трогали хранилище |
| `npm run verify:docs` | `scripts/check-docs.mjs`: Markdown-ссылки и якоря **плюс** упоминания файлов в обратных кавычках (например `` `src/storage/sqlite.ts:251` ``) | После правок документации; входит в `verify` |
| `npm run verify` | `test` → `build` → `verify:dist` → `verify:file` → `verify:docs` | **Перед сдачей** |
| `npm run bench` | `scripts/bench-storage.mjs` → `benchmarks/storage.json` | Оценка влияния правок на слой хранения |

Вне npm-скриптов, вручную (Windows + PowerShell):
`scripts/build-android-icons.ps1` — конвертер `public/favicon.ico` в PNG всех
плотностей для `android/app/src/main/res/mipmap-*` (доступен и как `build:apk --icons`).

Неиспользуемые зависимости: `concurrently` и `jsdom` объявлены в `devDependencies`, но не используются ни одним скриптом и ни одной конфигурацией (`vitest.config.ts` → `environment: "node"`). Не рассчитывайте на них.

## 5. Обязательная проверка перед сдачей

```bash
npm run verify
```

Это `npm test` → `npm run build` → `npm run verify:dist` → `npm run verify:file`
→ `npm run verify:docs`. Сейчас проходит: 84 теста, `dist/index.html` ≈ 2.9 МБ одним файлом.

Дополнительно, по условию изменения:

| Когда | Команда | Что ловит |
|-------|---------|-----------|
| Трогали `vite.config.ts`, `vite.dev.config.ts`, `vite.shared.ts`, CSP, добавили зависимость с ассетами | `npm run verify:file` | Всё, что ломается под `file://`: абсолютные `src`/`href` (уедут в корень диска), `url(/…)` в CSS, `fetch("/…")`, `import("/…")`, `new Worker("/…")`, `new URL(x, location.origin)` (origin у `file://` — строка `"null"`), `serviceWorker.register("/…")`, следы `base: "/"`, ссылки на `localhost` и типовые порты dev-сервера. Скрипт маскирует base64-блоки (~900 КБ), чтобы случайные последовательности внутри данных не давали ложных срабатываний, и не считает строковый литерал `"<script>"` в бандле вторым тегом |
| Запускали Electron и меняли схему/хранилище | `npm run verify:db` | Нечитаемый или обрезанный образ БД, пустой файл, неверная сигнатура, расхождение версии схемы с `src/storage/schema.ts`, отсутствующая таблица или колонка. Скрипт **строго читающий** и сам импортирует `schema.ts`, поэтому ожидания не разъезжаются с приложением |
| Меняли типы | `npm run typecheck` | Ошибки типов; в `tsconfig.json` включены `strict`, `noUnusedLocals`, `noUnusedParameters`, а также `capacitor.config.ts` |
| Меняли структуру папок | `npm run map` | Расхождение `project-map.json` с реальностью (`issues.undocumented`, `issues.missingModules`) |

Отдельно от `verify`:

| Когда | Команда | Что ловит |
|-------|---------|-----------|
| Правили документацию, переименовывали файл или скрипт | `npm run verify:docs` | Битые Markdown-ссылки и якоря, а также упоминания файлов в обратных кавычках, которых больше нет на диске. Именно этот класс ошибок ловится только скриптом: в Markdown битая ссылка не выглядит ошибкой |
| Планируете релиз | `npm run build:win`, `npm run build:apk` | Собираются ли релизные пакеты; вывод скриптов перечисляет готовые файлы и их размеры |
| Публикуете релиз | `node scripts/publish-release.mjs --dry-run` | Расхождение версий, незакоммиченные правки, устаревшие артефакты — до того, как что-либо уедет на GitHub |
| Менялся интерфейс так, что это видно на телефоне (навигация, формы, оверлеи, символы) | `npm run build:apk` + установка на устройство, §3 | Ничем не покрывается: ни тестами, ни браузером. Список пунктов — в §3 «Проверка на реальном устройстве» |

`verify:db` **не входит** в `verify` — его запускают вручную, когда затронуто хранилище. `verify:file` и `verify:db` ничего не правят, только читают.

## 6. Структура проекта

```
/
```

## 7. Как добавить функцию

### 7.1 Новый раздел (экран)

1. **`src/lib/types.ts`** — добавить значение в `export type Tab`.
2. **`src/views/MySection.tsx`** — новый файл, экспорт вида `export function MySection()`. Данные брать из `useApp()` (`src/hooks/AppProvider.tsx`), своё состояние в модуле не хранить.
3. **`src/components/AppShell.tsx`** — добавить запись в массив `NAV`: `{ tab: "mySection", label: "Раздел", icon: Gauge }`. `NAV` используется трижды: сайдбар, мобильная нижняя лента (`≤ 900px`) и горячие клавиши `Alt+1…9` (индекс = порядок в массиве). Отдельная правка не нужна.
4. **`src/App.tsx`** — добавить `const MySection = lazy(() => import(...))` и кейс в `CurrentView()`. Экраны (кроме `Dashboard`) грузятся по требованию, чтобы сканер не тащил `jsqr`/`tesseract` в стартовый бандл.
5. Проверить: `npm test && npm run typecheck && npm run build`.

### 7.2 Новый компонент

Класть в `src/components/`, имя файла — `PascalCase.tsx`. Если он переиспользуем хотя бы в двух экранах — в `src/components/ui.tsx` (там уже `Modal`, `ConfirmDialog`, `Field`, `Segmented`, `Toggle`, `ProgressBar`, `StatusBadge`, `EmptyState`, `PageHeader`, `ToastHost`, `CategoryHex`, `TickerHex`, `FocusTrap`, `useAnimatedNumber`, `useFilePick`, `usePressFeedback`). Стили — существующими классами из `src/index.css`; новый класс добавляется рядом со своей тематической секцией, а не в конец файла.

### 7.3 Новый метод платформенного контракта

`PlatformBridge` (`src/platform/types.ts`) — это **интерфейс**, а не набор дефолтов. Новый метод обязан быть реализован **во всех трёх мостах**; `npm run typecheck` укажет на забытый, но «реализовать в windows и считать, что этого хватит» нельзя.

| Файл | Что добавить |
|------|--------------|
| `src/platform/types.ts` | метод в `interface PlatformBridge` (+ JSDoc по-русски) |
| `src/platform/webBridge.ts` | рабочая реализация по умолчанию через браузер |
| `src/platform/windows/electronBridge.ts` | делегирование в `window.electronAPI` с откатом на web-мост, если IPC нет |
| `src/platform/android/capacitorBridge.ts` | реализация через плагины Capacitor (`@capacitor/app`, `@capacitor/local-notifications`, `@capacitor/filesystem`, `@capacitor/share`) **или честная заглушка** `async () => false`. Наличие плагина проверяйте через `Capacitor.isPluginAvailable`, а не «на глаз»: `features` Android-моста вычисляется по факту |
| `src/lib/electronApi.ts` | сигнатура в `interface ElectronAPI` |
| `preload.cjs` | метод в объекте `electronAPI` + `ipcRenderer.invoke('<канал>')`; **обновить список каналов в шапке файла** |
| `electron-main.cjs` | `ipcMain.handle('<канал>', …)` с **точно тем же** именем канала |

Правила, которые здесь нельзя нарушать:

- **Имена каналов обязаны совпадать** в `preload.cjs` и `electron-main.cjs`. Сейчас их девять: `open-data-folder`, `load-db`, `save-db`, `clear-db`, `app-version`, `save-text-file`, `pick-text-file`, `notify`, `set-tray`. Проверяйте оба места.
- **`preload.cjs` выполняется при `sandbox: true`.** Доступны только `require('electron')` и несколько встроенных модулей песочницы; `fs` и `path` недоступны. Всё, что нужно с диском, делает главный процесс.
- **Наружу через `contextBridge` не выставляются** модули, `ipcRenderer` и внутренние переменные — только `window.electronAPI` с функциями. Окно создаётся с `sandbox: true`, `nodeIntegration: false`, `contextIsolation: true`; `window.open` запрещён, навигация разрешена только внутрь каталога приложения.
- В `electron-main.cjs` ошибки **не глотаются**: причина и путь пишутся в лог до `return false`, а чтение файла ошибку пробрасывает наверх, а не подменяет `null`.

## 8. Работа с хранилищем

Слои: `src/storage/` (SQLite через `sql.js` + WASM) → фасад `src/lib/storage.ts` → состояние `src/hooks/AppProvider.tsx`. Приложение обращается к базе **только** через `storageService`.

### 8.1 Правила, которые нельзя обходить

- **Все записи идут через очередь `enqueue()`** (`src/storage/sqlite.ts`): `write`, `setFlag`, `clear`, `transaction`, `compact`. Внутри уже открытой транзакции (`this.txDepth > 0`) идём напрямую (`writeInTransaction`, `execFlag`, `compactNow`). Обход очереди приводит к двум реальным поломкам: два автосохранения сливаются в одну незавершённую транзакцию (чужой `ROLLBACK` откатывает уже возвращённый `true`, а удаление «устаревших» строк сносит только что записанное).
- **Снапшот сохраняется только после `COMMIT`.** `db.export()` внутри транзакции закрывает её (`cannot commit - no transaction is active`).
- **Ошибка чтения ≠ «базы нет».** `load-db` возвращает `null` только когда файла нет; при ошибке — причина в лог и отказ наверх. `storageService.load()` пробрасывает ошибку, `AppProvider` ставит `loadBlocked` и блокирует автосохранение, в настройках появляется «Повторить чтение». Иначе демо-данные затрют реальные.
- **`false` от `save-db` — это исключение**, а не «сохранено» (`src/storage/snapshots.ts`).
- **Очистка сохраняет флаги миграции** `migration.legacy.v1*` и `migration.legacy.v1.at`; остальные служебные отметки (например, `ui.onboarded.v1`) удаляются. Иначе данные «воскреснут» из legacy-ключа.
- **`clear()` возвращает промис**, и вызывающий обязан его `await`-ить до очистки состояния — иначе отложенный автосейв вернёт удалённое обратно.
- **`persistent` считается по факту** (тип снапшота + успех последней записи), а не жёстко `true`.

### 8.2 Добавить таблицу (новую коллекцию `AppData`)

1. `src/lib/types.ts` — добавить ключ в `CollectionKey` (`src/storage/types.ts`) и в `AppData`.
2. `src/storage/schema.ts` — запись в `COLLECTION_SPECS`: `table`, список `columns` (`id` — `TEXT PRIMARY KEY NOT NULL`), `indexes`. Колонка `doc` (полный JSON записи) добавляется автоматически `createTableOps()` — вручную её описывать не надо.
3. Там же: увеличить `SCHEMA_VERSION` и добавить шаг в `MIGRATIONS`: `{ version: N, name: "...", ops: () => [...] }`. Шаги **идемпотентны** (`IF NOT EXISTS` / `IF EXISTS`), применяются по `migrationOps(from, to)`.
4. Коллекция автоматически подхватывается в `read()` (SELECT `doc`), `write()` (дифф по `id` + UPSERT) и `clear()`. Отдельно ничего править не нужно.
5. `scripts/check-desktop-db.mjs` подхватит таблицу сам (импортирует `schema.ts`), но её зашитая копия `FALLBACK_SCHEMA` устареет — её стоит синхронизировать вручную.
6. Тест в `tests/storage.test.ts` (round-trip, отсутствие дублей, удаление исчезнувших строк).

### 8.3 Добавить колонку в существующую таблицу

Значение уже есть в `doc` (JSON), но SQL-выборки идти не будут. Нужен шаг миграции с `ALTER TABLE … ADD COLUMN`, плюс `SCHEMA_VERSION + 1` и запись в `spec.columns`, если по колонке строится индекс.

Версия схемы лежит в `meta.schema_version`. База из **более новой** версии, чем приложение, читается, но запись в неё отключается (`assertWritable` → `locked`); пользователь увидит это в настройках.

## 10. Соглашения по коду

**Язык и комментарии.** Интерфейс и сообщения об ошибках — по-русски. Комментарии — по-русски и объясняют *почему*, а не *что*: в проекте много пояснений в стиле «почему именно так», и это часть культуры кода. Идентификаторы — по-английски. Ошибки ловят в `catch` и пишут в `console.error` с префиксом (`[storage]`, `[main]`, `[preload]`, `[renderer]`), а не глотают.

**Имена и структура.** Файлы компонентов и экранов — `PascalCase.tsx`, модулей логики — `camelCase.ts`, скрипты — `kebab-case.mjs` (ESM; `package.json` объявляет `"type": "module"`, а часть скриптов импортирует `.ts`). Классы в CSS — `kebab-case` (`.nav-item-active`, `.jcell-amount`). Компоненты функциональные и типизированные, общее состояние — `useApp()` из `src/hooks/AppProvider.tsx`; компонент не ходит в хранилище напрямую. Классы склеиваются через `cn()` (`src/utils/cn.ts`: `clsx` + `tailwind-merge`).

**CSS — важно понимать.** `src/index.css` начинается с `@import "tailwindcss";`, а весь остальной файл объявлен **вне слоёв Tailwind** (в нём нет ни одного `@layer`). Каскад слоёв в Tailwind 4 — `theme, base, components, utilities`, и **любое правило без слоя перебивает утилиты**. Отсюда сюрпризы порядка: `className="btn px-2"` — `padding` из `.btn` победит `px-2`, и это не баг, а принятая схема. Не «чините» это переносом в `@layer components`, не проверив, что не поедет вёрстка.

Смежная ловушка: `color-mix()` **не принимает процент больше 100 %** — такое значение делает всё объявление невалидным, браузер его отбрасывает и берёт унаследованное/начальное значение. Для `color` и `border-color` это выглядит как «цвет молча стал `currentColor`»: правило перестало работать без единой ошибки в консоли. Держите доли в диапазоне 0–100 %.

Ещё две особенности того же файла:

- Цвета и размеры тем — CSS-переменные из `:root` / `[data-theme="..."]`; атрибут ставит `AppProvider` (`document.documentElement.dataset.theme`). Новая тема = блок переменных в `index.css` + запись в `THEMES` (`src/lib/constants.ts`).
- Деградация оформлена блоками `html[data-perf="low"]` (слабое устройство), `html[data-perf="mid"]` (средний: только фоновые свечения и `backdrop-filter` карточек) и `html[data-motion="reduced"]` (системная настройка); атрибуты ставит `src/hooks/useCapabilities.ts`. Анимация — только `transform`/`opacity`, иначе возвращается reflow.
- **Правила для телефона живут в `@media (pointer: coarse)`** (`index.css`, отдельный блок) и больше нигде: зоны нажатия 44 px, кегль полей от 16 px, `scroll-margin-block` для автопрокрутки. Вёрстка настраивалась мышью, и общие правила для этого трогать нельзя. Рядом — блок `@media (max-width: 900px)` для тостов, которые на телефоне поднимаются над нижней лентой.
- **Безопасные зоны — переменные `--sat/--sar/--sab/--sal`** в `:root`, читающие `env(safe-area-inset-*, 0px)`. При `targetSdk 35+` приложение рисуется под системными панелями, поэтому любой элемент, прижатый к краю экрана, обязан их учитывать. Фолбэк `0px` — на десктопе значения равны нулю. `viewport-fit=cover` в `index.html` нужен, чтобы `env()` вообще что-то возвращал.
- **Знаки валют — только через `readSymbol()`** (`src/lib/utils.ts`). `Intl.NumberFormat` со `style: "currency"` подставляет символ сам, и подменить его после нельзя, а в системном шрифте телефона ₽ (U+20BD) может отсутствовать: суммы рисуются как `557 885 ▯`. `readSymbol` проверяет глиф измерением ширины в канвасе и возвращает текстовую замену.

**Иконки категорий.** `src/components/ui.tsx` → `CATEGORY_ICONS: Record<string, LucideIcon>` — имя иконки (`briefcase`, `cart`, `utensils`, …) → компонент из `lucide-react`. Сами категории — `src/lib/constants.ts` → `CATEGORIES` (`label`, `color`, `type`). Новая категория = строка в `CATEGORIES` + иконка в `CATEGORY_ICONS`. Формы используют `CategoryPicker` (сетка плиток), а не нативный `<select>`: в `<select>` иконку показать нельзя.

**Брендовые значки.** `src/components/BrandIcons.tsx` — инлайновые SVG (`TelegramIcon`, `BoostyIcon`) с `fill="currentColor"` и `aria-hidden`. Раньше здесь стояли эмодзи «✈️» и сердечко, что не логотипы. Значок Boosty — монограмма в фирменном `#7B2FF7`, потому что официальный вектор проверить не удалось; если появится официальный SVG, меняется только тело компонента.

**Анимации.** Скорость задаётся в единицах **в секунду** через `src/animations/ticker.ts` (delta-time; `MAX_DELTA_MS` режет длинный кадр); переходы — `src/animations/waapi.ts` с `resolveMotionPlan` и `stagger` (лимит одновременных анимаций). Ветка деградации обязана применять конечное значение (`applyFinal`), иначе прогресс-бар залипнет на нуле. Перед следующей анимацией модуль отменяет свои прежние (`cancelOwn`) — список анимаций не должен расти.

Ручные описания (назначение, слой, ключевые экспорты) лежат в `map.config.ts`; фактические символы, размеры и рёбра импортов сканируются с диска. Карта решает две задачи: экономия времени (не читать весь код) и контроль архитектуры (видно, что подсистема лежит в правильном каталоге).

Разделы `project-map.json` (последняя генерация: 71 файл, 30 модулей, 276 символов):

| Раздел | Содержимое |
|--------|-----------|
| `modules/` | путь, назначение, `layer`, `exports`, `depends-on`, `used-by` |
| `symbols/` | индекс `Имя → { file, line, type }`; приоритет у файла-определения, а не у реэкспорта |
| `data-flow/` | пять именованных потоков (`app-start`, `write-transaction`, `read-list`, `capabilities-degrade`, `export-backup`), агрегаты по областям, рёбра импортов |
| `task-history/` | крупные задачи со статусом и списком файлов |
| `files/`, `areas/`, `layers/`, `stats/` | плоский список файлов, каталоги верхнего уровня, слои, счётчики |
| `issues/` | `missingModules` (модуль описан, а файла нет) и `undocumented` (файл есть, а описания нет) |

**Когда запускать.** После добавления, переименования или удаления модуля, а также после крупных правок в структуре папок. Новый файл в `src/`, `tests/` или `scripts/`, о котором нет записи в `map.config.ts`, попадёт в `issues.undocumented` — это сигнал, а не ошибка.

Git hook на обновление карты **не настроен**: каталог сейчас не под git (см. §12), ставить `husky` было не на что. Когда репозиторий станет под git — имеет смысл вызвать `npm run map` из `pre-commit`.

## 12. Ловушки окружения

1. **Сеть.** Доступен только реестр npm. `github.com` и CDN заблокированы; зеркала Tsinghua/NJU для Electron отдавали `ECONNRESET`, рабочим оказалось `mirrors.huaweicloud.com/electron` — отсюда ручная установка бинаря (§2).
2. **Electron-бинарь ставится отдельно.** `node_modules/electron` может быть без `dist/`; лечится ручной распаковкой (§2), а не повторным `npm install`.
3. **`private: true` в `package.json`** — пакет не публикуется в npm. Это правильно, но нужно знать при попытке `npm publish` / `npm version`.
4. **`package-lock.json` в `.gitignore` — риск для воспроизводимости сборок.** Файл на диске есть, но в репозиторий не попадёт: у другого разработчика разъедутся транзитивные версии (особенно `^`-диапазонов `jsqr`, `tesseract.js`, `sql.js`, `electron`, `vitest`), и баг проявится только у него. Рекомендация: убрать `package-lock.json` (и, вероятно, `yarn.lock`, `pnpm-lock.yaml`, `*.lock`) из `.gitignore` и коммитить lock-файл. Там же `dist-*`, который накрывает `dist-electron`.
5. **Два `index.html` — не дубль.** `index.html` → `src/main.tsx` (пользователь, без DevTools), `index.dev.html` → `src/main.dev.tsx` (разработчик). Менять нужно тот, который соответствует `build.rollupOptions.input` в нужном конфиге. В `index.html` иконка подключена как `./favicon.ico` — абсолютный `/favicon.ico` под `file://` уедет в корень диска.
6. **Мобильный слой собран, но требует JDK 21.** `android/` и `capacitor.config.ts` в репозитории есть, APK собирается (`build:apk`). Подводные камни, из-за которых сборка выглядит «сломанной»: AGP берёт компилятор из тулчейна с `languageVersion = 21`, поэтому физически нужен **JDK 21** (в системе обычно только 25); Gradle 9.3.1 требует, чтобы `pluginManagement` был **первым оператором** `settings.gradle`; зеркало Maven Central обязано быть и в `settings.gradle`, и в `buildscript.repositories` корневого `build.gradle`; `rootProject.buildDir` удалён в Gradle 9 (нужен `layout.buildDirectory`); TLS рвётся, поэтому `gradlew` запускается с повторами. Отдельно: `capacitor.config.ts` → `App.disableBackButtonHandler` обязан остаться `false`, иначе нативный обработчик кнопки «Назад» не создаётся вовсе.
7. **Ни одна сборка не подписана.** Установщик Windows идёт без сертификата (SmartScreen покажет «Неизвестный издатель»), ключ Android самоподписанный — Google Play его не примет без Play App Signing, а `versionCode` в `android/app/build.gradle` поднимается вручную. Это ограничение окружения, а не дефект сборки; что именно нужно для подписи — в `README.md` и `docs/Выполнение-ТЗ.md` §7б.
8. **OCR чеков требует интернет.** `tesseract.js` создаёт воркер и тянет языковые данные по сети; единственный разрешённый внешний домен в CSP — `cdn.jsdelivr.net`, и он указан **в двух директивах**: `connect-src` (за wasm-ядро и языковые данные) и `script-src` (воркер создаётся из `blob:`-URL и внутри себя делает `importScripts` к этому хосту, а `importScripts` проверяется по `script-src` унаследованной политики). Уберите второй — распознавание чеков сломается одинаково и в Electron, и на Android, причём без внятной ошибки. Офлайн распознавание не работает (лечится только вендорингом, ~15 МБ). В `Scanner.tsx` при ошибке пользователю честно показывают «Проверьте интернет».
9. **CSP добавляется только при сборке.** Плагин `cspPlugin` в `vite.config.ts` имеет `apply: "build"`: в dev он сломал бы HMR-клиент Vite. При правке политики обязательно прогоняйте `npm run verify:file` — приложение живёт под `file://`, и каждый новый внешний ресурс там ломается иначе, чем под `http://`.
10. **Два неиспользуемых файла с JSX внутри `.ts`** — `src/hooks/useKeyboard.ts` и `src/lib/engine1.ts`. Они ломают `tsc`, поэтому исключены в `tsconfig.json` (и в `ignore` в `map.config.ts`), но не удалены, чтобы не трогать чужую работу. Не используйте их как образец.
11. **Решение о лицензии принято, но не в пользу открытой.** Приложение распространяется как закрытая бета с ранним доступом: `package.json` → `"license": "UNLICENSED"`, `license.txt` — условия использования бета-версии (их показывает установщик NSIS). Лицензионные пометки в футер не возвращать — там только «Бета» и версия. Открытая лицензия на исходники не заводится: она противоречит модели раннего доступа. Разбор — в `docs/Лицензирование.md`.
12. **Интерфейс, настроенный в десктопном браузере, ломается на телефоне.** Ни зоны нажатия, ни кегль полей, ни нижняя навигация, ни безопасные зоны не проверяются ни тестами, ни взором в браузере: 9 пунктов меню в 393 CSS-пикселях — это 2,5 экрана горизонтальной прокрутки, и `pointer: coarse` в браузере на десктопе не включается. После правок интерфейса — установка APK и проверка по списку из §3 («Проверка на реальном устройстве»).
13. **Бэкап ОС на Android запрещён намеренно, поэтому экспорт обязателен.** `allowBackup="false"` плюс `res/xml/{data_extraction_rules,backup_rules}.xml` закрывают и облачную копию Google, и перенос «телефон → телефон»: приватное хранилище (IndexedDB с базой плюс дубль в `localStorage`) уходило в облако целиком и могло восстановиться на чужом устройстве молча. Побочный эффект: восстановить базу после очистки данных приложения больше нечем, кроме файла экспорта. `adb shell pm clear` без предварительного экспорта необратим.
14. **`minifyEnabled false` — сознательное решение, а не упущение.** Сжатие R8 дало бы экономию 1–1,5 МБ, но неправильные keep-правила ломают вызовы нативных мостов `@capacitor/*` молча. Включать только с полной регрессией на устройстве.

## 13. Релиз

Публикация приватного бета-релиза — одна команда: `node scripts/publish-release.mjs`. Скрипт сам создаёт приватный репозиторий `dev-aitechpro/nexus-finance-beta`, если его нет, сам собирает оба артефакта и загружает их в релиз с меткой «предварительный». Ниже — порядок, который нужно соблюсти **до** запуска: часть вещей скрипт проверит и остановит публикацию, а часть останется на вас.

### 13.1 Порядок действий

| № | Шаг | Команда или действие | Что проверяем перед тем, как идти дальше |
|---|-----|----------------------|----------------------------------------------|
| 1 | Поднять версию в трёх файлах | см. §13.2 | Скрипт сверяет `package.json` и `android/app/build.gradle` и падает при расхождении — но `APP_VERSION` в интерфейсе он не правит |
| 2 | Записать `CHANGELOG.md` | раздел `## [<версия>]` с датой | Без него скрипт возьмёт раздел `[Невыпущенные]` и предупредит, а запишет в релиз то, что там лежит |
| 3 | Прогнать проверки | `npm run verify`, `npm run typecheck` | 84 теста, сборка, `verify:dist`, `verify:file`, `verify:docs` |
| 4 | Закоммитить | `git add -A && git commit -m "1.0.0-beta.1"` | Скрипт откажется публиковать при незакоммиченных правках, иначе в репозиторий уедет старый коммит, а соберётся новое. Исключение: если коммитов ещё не было ни одного, скрипт сделает первый коммит сам |
| 5 | Опубликовать | `node scripts/publish-release.mjs` | Токен в `GITHUB_TOKEN` (см. §13.4). Скрипт сам вызывает `scripts/build-windows.mjs` и `scripts/build-android.mjs --release` |
| 6 | Проверить результат | открыть страницу релиза, поставить APK на устройство | Три файла на месте, версия в имени совпадает с `package.json` |
| 7 | Обновить установленное приложение | собрать и запустить релизную сборку либо поставить релизный APK поверх старого | Приложение должно предлагать `1.0.0-beta.1`, а не молчать. В режиме разработчика проверка обновлений не выполняется вовсе: `electron-updater` пропускает её для неупакованного приложения |

**Шаг 5 целиком, одной строкой** (PowerShell):

```powershell
$env:GITHUB_TOKEN = "github_pat_…"; node scripts/publish-release.mjs
```

**Ошибки публикации и что делать** — [Решение-проблем.md](Решение-проблем.md) §14. Там же блокер этой машины: `api.github.com` отсюда недоступен, поэтому команду запускают из сети, где GitHub доступен.

### 13.2 Версия живёт в трёх файлах

Поднимать надо **везде**: три файла, четыре значения. Иначе релиз разъедется по платформам, а в интерфейсе останется старый номер.

| Место | Поле | Чем используется | Что будет, если забыть |
|-------|------|------------------|------------------------|
| `package.json` | `version` | electron-builder подставляет её в имя файла установщика и в файл метаданных канала; `scripts/publish-release.mjs` берёт отсюда версию и имя тега | Соберётся файл `… Setup 1.0.0.exe` с прошлой версией в имени, и скрипт это поймает |
| `android/app/build.gradle` | `versionName` | версия в APK и в «О приложении» | Скрипт упадёт на сверке версий до загрузки чего бы то ни было |
| `android/app/build.gradle` | `versionCode` | **целое число, строго больше предыдущего.** Инкремента нет | Play отвергнет сборку, `adb install -r` не поставит APK поверх установленного |
| `src/lib/constants.ts` | `APP_VERSION` | подпись в футере и на экране настроек; значение оттуда же возвращает веб-мост, если нативный `App`-плагин недоступен | Пользователь увидит в интерфейсе старую версию, хотя установлен релизный файл |

`versionCode` и `versionName` в `build.gradle` держатся рядом намеренно: правится одно место, обе строки поднимаются вместе.

### 13.3 Что делает `scripts/publish-release.mjs`

Восемь шагов, каждый печатает номер и результат; ненулевой код возврата означает, что публикация остановлена:

1. **Версия.** `package.json` ↔ `android/app/build.gradle`; `1.0.0-beta.1` разбирается как semver с пре-суффиксом. Расхождение или не-semver — стоп.
2. **Токен.** `GET /user`: токен принят, показан аккаунт и его scopes. Токена в `GITHUB_TOKEN` нет — стоп с инструкцией, как его получить.
3. **Репозиторий.** `GET /repos/dev-aitechpro/nexus-finance-beta`; если 404 — `POST /user/repos` с `private: true`. Если репозиторий есть и он **публичный**, скрипт останавливается: это не тот случай.
4. **Локальный git.** Проверка чистоты рабочего дерева, коммит, тег `v<версия>`, `git push` ветки и тега. Повторный запуск ничего не ломает: существующие репозиторий, тег и релиз переиспользуются.
5. **Сборка.** `scripts/build-windows.mjs` (установщик + portable) и `scripts/build-android.mjs --release`.
6. **Проверка артефактов.** Файл есть, размер не нулевой, **в имени есть текущая версия** (артефакт от `1.0.0` в релиз `1.0.0-beta.1` не пройдёт — так уже уезжала устаревшая сборка), артефакт не старше последней правки исходников, файл метаданных канала описывает ту же версию.
7. **Релиз.** `GET /releases/tags/v<версия>`, затем `POST /releases` с `prerelease: true` и `make_latest: "false"`, чтобы бета не стала «последним релизом» для стабильного канала.
8. **Загрузка.** Три обязательных файла (установщик, portable, APK) плюс метаданные канала и `.blockmap` — они обязательны для автообновления, хотя в списке «трёх артефактов» их нет. Хост отдельный: `uploads.github.com`, через `api.github.com` загрузка файлов не идёт. Метаданные кладутся **под обоими именами** — `beta.yml` (как велит `build.publish.channel`) и `latest.yml`: приватный репозиторий читает через `PrivateGitHubProvider`, а он ищет именно `latest.yml` и настройку `channel` не учитывает.

Флаги: `--dry-run` (всё проверить, ничего не создавать), `--skip-build` (взять готовые артефакты), `--skip-apk`, `--skip-git` (оставить `git push` человеку), `--allow-dirty`, `--force-assets` (перезалить уже загруженные файлы), `--notes <файл>`. Полный список — `node scripts/publish-release.mjs --help`.

**Про токен и `git push`.** Токен передаётся git только на время команды, через `GIT_CONFIG_COUNT`/`GIT_CONFIG_KEY_0`/`GIT_CONFIG_VALUE_0` (git читает их как `-c` из окружения) с заголовком `Authorization: Basic`. Он не попадает ни в `.git/config`, ни в `git remote -v`, ни в список процессов, и после команды на диске не остаётся ничего. Remote при этом обычный, без токена: `https://github.com/dev-aitechpro/nexus-finance-beta.git`. Если push не прошёл, скрипт напечатает команды для ручной отправки и продолжит — релиз от кода в git не зависит.

**Почему в `build` именно так.** Три решения, которые выглядят неочевидно, но ломают релиз при «улучшении»:

- `nsis.differentialPackage: true` — по умолчанию electron-builder и так строит blockmap, но дефолт меняется между версиями, а от него зависит, качает обновление дельту или все 100 МБ. Явное `true` фиксирует поведение. По той же причине скрипт грузит `.blockmap` в релиз: без него первое обновление после `1.0.0-beta.1` скачает установщик целиком.
- **`artifactName` не задан, и задавать его в `win` нельзя.** Дефолт electron-builder уже осмысленный: `NEXUS Finance Setup ${version}.${ext}` для установщика и `NEXUS Finance ${version}.${ext}` для portable — версия в имени есть. А вот общий `win.artifactName` с шаблоном без «Setup» сделает оба файла одинаковыми, и один перезапишет другой. Если имена понадобится поменять, их разводят по секциям: `build.nsis.artifactName` и `build.portable.artifactName`. Скрипт проверяет это и останавливается с понятным сообщением, если имена совпали.
- **Пробелы в имени файла в релизе — не ошибка.** На диске файл называется `NEXUS Finance Setup 1.0.0-beta.1.exe`, а `electron-updater` ищет `NEXUS-Finance-Setup-1.0.0-beta.1.exe`: оба провайдера (`GitHubProvider` и `PrivateGitHubProvider`) заменяют пробелы на дефисы при построении адреса. Поэтому скрипт читает имя из файла метаданных и загружает установщик под именем с дефисами. Править шаблон `artifactName` ради этого не нужно.

### 13.4 Требования к токену

| Что | Значение |
|-----|----------|
| Источник | только переменная окружения `GITHUB_TOKEN`. Ни аргументом командной строки, ни файлом в проекте |
| Fine-grained PAT | репозиторий `dev-aitechpro/nexus-finance-beta` в Repository access; Contents: Read and write. Если репозиторий создаёт скрипт, ещё Administration: Read and write |
| Classic PAT | scopes `repo` (приватный репозиторий) |
| Где взять | GitHub → Settings → Developer settings → Personal access tokens |
| Почему не в файле проекта | файлов с токеном в проекте нет, и `.gitignore` это закрепляет: `*.token`, `gh-token.txt` и `release.local.json` запрещены. Секрет не должен переживать команду и попадать в коммит |

### 13.5 Что делать, если релиз получился плохой

1. **Убрать релиз.** На странице релиза → Delete release. Один клик, файлы исчезают, метаданные канала перестают отдаваться.
2. **Убрать тег.** `git push origin :refs/tags/v1.0.0-beta.1` и удалить тег в интерфейсе GitHub (удаление тега на сервере локальный тег не стирает).
3. **Не перезаливать тот же номер версии.** Релиз `1.0.0-beta.1`, который уже увидели пользователи, перевыпускать нельзя: тег указывает на старый коммит, а `electron-updater` умеет только «новее текущей». Поднимайте версию: `1.0.0-beta.2` во всех строках §13.2 и повторяйте шаги 2–5.
4. **Пересобрать, а не перезалить.** Даже после `--force-assets` файл в релизе лежит с прежним `sha512` в метаданных; если сборка изменилась, метаданные тоже должны быть новыми. Проще пересобрать и выпустить следующий номер.

### 13.6 Что ещё не закрыто для публичного релиза

- **Ни одна сборка не подписана** (§12, пункт 7): установщик идёт как «Неизвестный издатель», а ключ Android самоподписанный. Для приватной беты это нормально, для публичного релиза — нет.
- ~~**Лицензия не выбрана**~~ — закрыто: `license.txt` содержит условия бета-раннего доступа, `UNLICENSED` остаётся точным.
- ~~**`repository.url` указывает на `yourusername`**~~ — закрыто: `github.com/dev-aitechpro/nexus-finance-beta`.
