# NEXUS Finance

Личное приложение для учёта личных финансов: доходы и расходы, бюджеты, цели,
инвестиции, регулярные платежи и подписки. React 19 + TypeScript + Vite 7,
настольная обёртка Electron 43, мобильная обёртка Capacitor 8 (Android), база
SQLite (`sql.js`, WebAssembly), русский интерфейс. Данные хранятся локально — ни
сервера, ни аккаунтов, ни облака.

Готовые сборки: установщик и portable-версия для Windows (NSIS, `npm run
build:win`) и APK для Android (`npm run build:apk`, `npm run build:apk:debug`).

## Возможности

### Разделы приложения

Навигация перечислена в `src/components/AppShell.tsx`, экраны — в `src/views/`
(7 файлов, 9 экранов; всё, кроме обзора, подгружается по требованию).

| Раздел | Что в нём |
|--------|------------|
| **Обзор** | Итоги месяца, график движения денег, разбивка расходов по категориям, статус бюджетов и целей, ближайшие платежи, сводка по портфелю |
| **Транзакции** | Журнал операций: доходы и расходы, поиск, фильтры, постраничный просмотр, массовое выделение, редактирование и удаление |
| **Платежи** | Подписки и фиксированные платежи: период, день списания, напоминание, автоплатёж; платежи следующего месяца создаются заранее и ждут подтверждения |
| **Подтвердить** | Накопившиеся платежи: подтвердить или пропустить с переносом на следующий срок |
| **Бюджет** | Лимиты по категориям, расход против лимита, предупреждения о перерасходе |
| **Цели** | Цели накопления с суммой, сроком и расчётом ежемесячного вклада |
| **Инвестиции** | Портфель по тикерам: количество, цена покупки и текущая, доходность, график роста, сложный процент, срок достижения цели. **Котировки симулируются локально** (переключатель «Симуляция котировок»), внешние источники цен не подключены |
| **Сканер чеков** | Камера: распознавание QR-кода (`jsqr`) и текста чека (`tesseract.js`, языки `rus`+`eng`); загрузка JPG/PNG/WEBP, вставка из буфера. Из распознанного текста предлагаются суммы — категорию вы выбираете сами |
| **Настройки** | Тема, валюта, масштаб шрифта, экспорт/импорт JSON, демо-данные, очистка, сведения о хранилище, значок в трее, версия приложения |

### Данные и хранение

- Локальная база SQLite (движок `sql.js`, WASM) — 8 таблиц данных плюс служебная
  `meta`: `transactions`, `subscriptions`, `fixed_payments`, `budgets`, `goals`,
  `investments`, `pending_payments`, `skipped_payments`. Версия схемы — 1.
- В Electron база лежит файлом и переживает перезапуск и чистку кэша; в браузере
  она хранится в IndexedDB, а при её недоступности — в `localStorage`, и как
  последний вариант в памяти сеанса. Приоритет выбирается автоматически.
- Данные из старого `localStorage` переносятся автоматически одной транзакцией;
  исходный ключ хранится 30 дней для отката, срок виден в настройках.
- Экспорт и импорт полного снимка в JSON (импорт сливает данные без дублей по
  ID). «Сжать базу» выполняет `VACUUM`.

### Оформление и производительность

- Три темы: Cyberpunk, Dark Minimal, Light Minimal. Четыре валюты, три масштаба
  шрифта.
- Мобильная вёрстка настраивалась на реальном телефоне (Infinix X6858, Android 16,
  ≈393 CSS-пикселя по ширине): нижняя лента из пяти пунктов сеткой
  `minmax(0,1fr)`, остальные разделы — в шторке «Ещё»; безопасные зоны
  `env(safe-area-inset-*)`; зоны нажатия и кегль полей увеличены **только** при
  `pointer: coarse` (десктоп не тронут). Знак валюты проверяется на наличие глифа
  и при необходимости заменяется текстом («557 885 руб.») — в системном шрифте
  телефона ₽ отсутствует.
- Режим экономии ресурсов `data-perf="low"` (по числу ядер и объёму памяти, либо
  принудительно через `?perf=low` в адресе) и поддержка системной настройки
  `prefers-reduced-motion`: анимации, размытия и тени отключаются. Уровень `mid`
  тоже описан правилами — отключаются фоновые свечения и размытие карточек.
- Анимации считаются в цикле с delta-time, поэтому скорость не зависит от
  60/144 Гц; тяжёлые экраны (в том числе сканер) не входят в стартовый бандл.

## Требования

| Что | Требование |
|-----|-----------|
| Node.js | `^20.19.0` или `>=22.12.0` — это ограничение Vite 7.3.2. Проверено на Node 24.21.0 |
| npm | Штатный из поставки Node.js |
| Браузер | Любой современный: нужен WebAssembly и IndexedDB. Приватный режим с отключённым IndexedDB останется работать, но данные не переживут вкладку |
| Windows | Только для настольной версии (Electron) и сборки установщика |
| Android SDK | Только для сборки APK: platforms 35/36/37 и build-tools 36 достаточно. Скрипт находит SDK сам через `ANDROID_HOME`, `android/local.properties` или стандартные каталоги |
| JDK 21 | **Обязателен для сборки APK:** Android Gradle Plugin берёт компилятор из тулчейна с `languageVersion = 21`. Если в системе только JDK 25, положите JDK 21 в `%USERPROFILE%\.gradle\jdks\` или укажите путь в `NEXUS_JDK21` — `scripts/build-android.mjs` найдёт его сам |

Отдельных системных пакетов для веб- и настольной сборки не нужно: SQLite — это
WebAssembly, нативных модулей в зависимостях нет. Для APK нужны только Android
SDK и JDK 21.

Для `npm run map` (генератор карты проекта) нужен Node, умеющий импортировать
TypeScript напрямую — проверено на Node 24.21.0.

### Если Electron не запускается

Бинарь Electron (`node_modules/electron/dist/electron.exe`, версия —
`node_modules/electron/path.txt`) ставится вместе с пакетом. Если его нет:

1. удалите `node_modules/electron` и выполните `npm install` заново;
2. если загрузка с адресов Electron недоступна, укажите зеркало через
   `ELECTRON_MIRROR` при установке (в среде, где готовили этот проект, сработало
   зеркало `mirrors.huaweicloud.com/electron`).

Пока бинаря нет, обычный `npm run dev` (браузерный режим) работает полностью.

## Быстрый старт

### Вариант 1 — просто посмотреть в браузере

```bash
npm install
npm run dev
```

Откроется dev-сервер (по умолчанию `http://127.0.0.1:5173/`) с включёнными
DevTools. Данные в этом режиме хранятся в IndexedDB браузера.

### Вариант 2 — как настольное приложение

```bash
npm install
npm run build        # один самодостаточный dist/index.html
npm run electron:debug
```

`npm run electron` — то же самое, но без инспектора DevTools. Собранная
страница открывается по протоколу `file://`, весь JavaScript, CSS и WASM лежат
внутри `dist/index.html` (~2.9 МБ), а база — файлом в папке данных приложения.

Эквивалент одной командой: `npm run dev:desktop` (сборка + запуск с инспектором).

### Сборка установщика Windows

```bash
npm run build:win
```

Скрипт `scripts/build-windows.mjs` делает сборку повторяемой: сначала `vite build`,
затем `electron-builder --win --x64` с целями `nsis` и `portable` (шаг повторяется
до четырёх раз — соединение рвётся на первой TLS-сессии). Результат в
`dist-electron/`:

| Артефакт | Размер | Что это |
|----------|--------|---------|
| `NEXUS Finance Setup 1.0.0.exe` | ~100,3 МБ | установщик NSIS: выбор папки, ярлыки на рабочем столе и в меню «Пуск», лицензия из `license.txt` |
| `NEXUS Finance 1.0.0.exe` | ~100 МБ | portable-версия: запускается без установки, пишет данные рядом с собой или в профиль пользователя |
| `win-unpacked/` | — | распакованная сборка для отладки запуска и содержимого |

Внутри `win-unpacked/resources/app.asar` ровно шесть файлов: `dist/index.html`,
`dist/favicon.ico`, `public/favicon.ico`, `electron-main.cjs`, `preload.cjs`,
`package.json`. Ни исходников, ни `node_modules`, ни документации там нет.

Сборка проверена запуском из отдельного временного каталога **без папки
проекта**: приложение стартует, читает и пишет базу, трей работает, на месте все
девять методов `window.electronAPI`. То есть установщик автономен и не
рассчитан на файлы репозитория.

**Требует сети** при первом запуске: `electron-builder` скачивает NSIS и
`winCodeSign` (зеркало бинарей задаёт сам скрипт, переопределяется переменной
`ELECTRON_BUILDER_BINARIES_MIRROR`). Сам Electron не качается заново — берётся
из `node_modules/electron/dist`, потому что зеркала Electron отдают архив, но не
`SHASUMS256.txt`, на котором `@electron/get` падает. Если бинаря нет, скрипт
скажет об этом и завершится.

**Установщик не подписан.** Сертификата нет, поэтому Windows SmartScreen
покажет предупреждение «Неизвестный издатель», а приложение в свойствах exe будет
помечено как «не проверено». Это ограничение, а не дефект сборки. Чтобы убрать
предупреждение, нужен сертификат подписи кода (OV или EV) и его установка в
хранилище доверенных сертификатов; технически это делается полями
`build.win.certificateFile` / `certificatePassword` (или переменными
`CSC_LINK` / `CSC_KEY_PASSWORD` для PFX) в секции `build` файла `package.json`,
плюс желательно `build.win.signtoolOptions` для серверной метки времени.

### Сборка Android (APK)

```bash
npm run build:apk          # release
npm run build:apk:debug    # debug
```

Скрипт `scripts/build-android.mjs` находит Android SDK и JDK, ищет **JDK 21** и
передаёт его Gradle, синхронизирует веб-ассеты (`npx cap sync android`:
`dist/` → `android/app/src/main/assets/public`, с проверкой, что `index.html`
совпал по размеру), затем запускает `gradlew :app:assembleDebug` /
`:app:assembleRelease` с повторами — сеть периодически рвёт TLS, и без повторов
сборка выглядит «сломанной». В конце печатается путь, размер и badging каждого
APK. Полезные ключи: `--icons` (перегенерировать иконки), `--no-sync`,
`--retries 12`, `--clean`, `--with-web`.

Готовые файлы:

| Артефакт | Размер | Подпись |
|----------|--------|---------|
| `android/app/build/outputs/apk/release/app-release.apk` | 4,39 МБ | самоподписанный ключ RSA-4096, схемы v2 + v3 |
| `android/app/build/outputs/apk/debug/app-debug.apk` | 6,73 МБ | отладочный ключ |

Проверенные параметры пакета: `package=com.nexus.finance`, `versionName 1.0.0`,
`versionCode 1`, `minSdk 24`, `targetSdk 36`, метка `NEXUS Finance`;
разрешения `CAMERA`, `POST_NOTIFICATIONS`, `INTERNET`. `VIBRATE`, `WAKE_LOCK` и
`RECEIVE_BOOT_COMPLETED` объявлялись шаблоном Capacitor, но приложением не
использовались и удалены через `tools:node="remove"`; добавлены
`android:usesCleartextTraffic="false"` и `android:windowSoftInputMode="adjustResize"`.
Бэкап ОС запрещён: `allowBackup="false"` плюс `res/xml/data_extraction_rules.xml` и
`res/xml/backup_rules.xml` — см. «Резервная копия» ниже.

Подпись release настраивается в `android/app/build.gradle` (блок
`signingConfigs`) и читается из `android/keystore.properties` — файла, который
лежит в `.gitignore` вместе с `android/nexus-release.jks`. Ключ генерируется
`keytool`, команда записана в самом `keystore.properties`. **Если файла нет,
release собирается неподписанным** — `cap sync` и Android Studio на чистой машине
из-за этого не падают.

## Где лежат данные

| Среда | Хранилище | Путь (Windows) |
|-------|-----------|----------------|
| Electron, запуск из исходников | Файл SQLite | `%APPDATA%\nexus-finance\nexus-data.sqlite` |
| Electron, установленная сборка | Тот же файл; имя папки определяется именем приложения при запуске | Точный путь показывает экран настроек |
| Браузер (dev-сервер или открытый `dist/index.html`) | IndexedDB `nexus-finance` → `snapshots` → `db.sqlite`; резерв — `localStorage` (`nexus.sqlite.snapshot`); при недоступности — память сеанса | Профиль браузера |
| Android (APK) | То же, что в браузере: запись в IndexedDB внутри приватного хранилища приложения | Не видна пользователю; экран настроек показывает `indexeddb://nexus-finance/db.sqlite` |
| Журнал главного процесса Electron | Текстовый файл, при росте больше 2 МБ предыдущий откладывается как `.oldlog` | `%APPDATA%\nexus-finance\logs\nexus-finance.log` |

Журнал нужен потому, что в собранном приложении окна консоли нет, а без файла
причина сбоя при запуске не осталась бы нигде.

**Важное отличие Android.** Кнопка «Открыть папку с данными» на мобильном
скрыта: у WebView нет пользовательской папки, открывать нечего. Зато
IndexedDB в WebView **стирается при очистке данных приложения** — на Windows
файл базы в `userData` переживает очистку кэша, на Android нет. И второе: раньше
приложение попадало в Google Backup, то есть приватное хранилище целиком
(IndexedDB с базой плюс дубль в `localStorage`) уходило в облако и могло молча
восстановиться на другом устройстве. Сейчас бэкап **запрещён**:
`allowBackup="false"`, а `res/xml/data_extraction_rules.xml` и
`res/xml/backup_rules.xml` закрывают и облачную копию, и перенос «телефон →
телефон» (проверено на устройстве: пакета нет в списке бэкапа). Побочный эффект
важнее самой правки: **система больше не восстанавливает базу, поэтому экспорт из
Настроек — единственная страховка, и он обязателен, а не рекомендация.**
Лечится по-настоящему только нативной файловой БД.

### Резервная копия

**Настройки → Данные и бэкап → «Экспорт в JSON»**. Сохраняется полный снимок:
транзакции, платежи, бюджеты, цели, инвестиции и настройки. Имя файла —
`nexus-finance-YYYY-MM-DD.json`. Импорт из JSON сливает данные без дублей по
идентификатору, поэтому импорт можно делать в непустую базу. В Electron открываются
нативные диалоги, в браузере — скачивание и выбор файла. В APK экспорт пишет
`@capacitor/filesystem` сначала в «Документы», а если запись запрещена
scoped storage — во внешнюю папку приложения и отдаёт файл системным меню
«Поделиться» (`<a download>` в WebView файл не сохраняет). Проверено на
устройстве: файл 52 КБ в публичной папке «Документы», валидный, все транзакции
на месте. На Android делайте экспорт регулярно — см. «Важное отличие Android»
выше: бэкап ОС отключён намеренно.

### Открыть папку с данными

**Настройки → Хранилище данных → «Открыть папку с данными»**. В Electron это
`shell.openPath` на папку приложения; в браузере кнопка показывает текущий
адрес хранилища, а не открывает Проводник. **В APK пункт скрыт:** у WebView нет
пользовательской папки, и вместо кнопки показан настоящий адрес
`indexeddb://nexus-finance/db.sqlite (внутри приватного хранилища приложения)`.
Там же видны драйвер, режим журнала, версия схемы, размер базы, ошибки чтения и
записи и состояние миграции.

## Структура проекта

| Путь | Что внутри |
|------|-----------|
| `electron-main.cjs` | Главный процесс Electron: окно, IPC хранилища и платформенных возможностей, значок в трее, журнал в файл |
| `preload.cjs` | Мост `contextBridge` → `window.electronAPI`; выполняется в sandbox-контексте |

## Что пока не сделано

Честный список ограничений — подробности в
[отчёте о выполнении ТЗ](docs/Выполнение-ТЗ.md), разделы 7, 7а, 7б и 7в.

- **Уведомлений о сторонних компонентах в сборке нет.** Тексты лицензий
  зависимостей (MIT, ISC, Apache-2.0 и другие) не попадают ни в `dist/`,
  ни в `app.asar`: при сборке комментарии вырезаются, а файлы лицензий в
  `package.json` → `build.files` не включены. Что нужно сделать и где им
  место — в [docs/Лицензирование.md](docs/Лицензирование.md) §4. Для
  закрытого продукта это не формальность: Apache-2.0 требует включать
  текст лицензии и уведомление об авторских правах вместе с
  распространяемым экземпляром.
- **Ни установщик Windows, ни APK не подписаны.** Сертификата подписи кода нет,
  поэтому SmartScreen покажет «Неизвестный издатель», а Android-ключ — тот, что
  сгенерирован локально. Что нужно для подписи — в разделе «Сборка установщика
  Windows» выше и в [docs/Решение-проблем.md](docs/Решение-проблем.md) §10.
- **APK проверен на одном устройстве, а не на нескольких:** Infinix X6858,
  Android 16 (SDK 36), ≈393 CSS-пикселя по ширине. Раньше приложение на телефоне
  вообще не запускалось — эмулятор в среде собрать было нечем, проверялся только
  состав пакета. Теперь запуск, база, «Назад», экспорт и настройки проверены, но
  **требует проверки**: камера и распознавание чеков (нужен доступ к
  `cdn.jsdelivr.net`), альбомная ориентация, анимация predictive-back, отправка
  файла системным меню «Поделиться» (в том числе открывается ли файл из публичной
  папки) и несколько разных устройств — от маленького экрана до Android 14 и ниже.
- **Системные уведомления не запрашиваются и не приходят.** Мост
  `PlatformBridge.notify()` на Android реализован корректно
  (`@capacitor/local-notifications`, запрос разрешения, `isExactNotification: false`),
  но **приложение его нигде не вызывает**: все сообщения пользователю идут
  внутренними всплывающими подсказками внутри окна. Разрешение
  `POST_NOTIFICATIONS` в манифесте объявлено, запроса не происходит — то есть
  обещать уведомления пока нельзя. `SCHEDULE_EXACT_ALARM` оставлен как «будет
  удалён вместе с отложенными уведомлениями».
- **Сжатие R8 выключено сознательно** (`minifyEnabled false`). Оно дало бы
  экономию 1–1,5 МБ, но требует полной регрессии на устройстве: неправильные
  keep-правила ломают вызовы нативных мостов, а ломаются молча. Это отдельная
  задача, а не оптимизация по умолчанию.
- **Для Google Play APK в текущем виде не годится:** подпись самоподписанная, а
  Google требует Play App Signing с загруженным ключом и `AAB` вместо `APK`.
  Целевая полка сейчас — ручная установка `.apk` на устройство.
- **Версия Android-пакета задана вручную:** `versionName "1.0.0"` и
  `versionCode 1` в `android/app/build.gradle` не связаны с полем `version` в
  `package.json`, автоматического инкремента `versionCode` нет. Это же относится
  к `versionName`: настройки показывают его из манифеста, но менять придётся
  руками.
- **Распознавание чеков требует интернета:** `tesseract.js` подгружает воркер и
  языковые данные с CDN. Офлайн сканирование не работает. Из-за этого же пришлось
  разрешить `cdn.jsdelivr.net` не только в `connect-src`, но и в `script-src`
  политики безопасности: воркер создаётся из `blob:`-URL и внутри себя делает
  `importScripts(...)` к этому хосту, а `importScripts` проверяется по
  `script-src`.
- **Сборка установщика и APK требуют сети** при первом запуске (см. выше).
- **База на Android стирается при очистке данных приложения** — IndexedDB в
  WebView удаляется вместе с приложением. Бэкап ОС, который раньше страховал эту
  потерю, теперь **запрещён** (`allowBackup="false"` плюс
  `res/xml/{data_extraction_rules,backup_rules}.xml`), поэтому страховкой остался
  только экспорт в JSON — он обязателен, а не рекомендация. Полностью лечится
  нативной файловой БД.
- `sql.js` держит базу в памяти целиком и пишет на диск снапшот, а
  `PRAGMA journal_mode = WAL` на такой базе настоящего WAL не даёт — настройка
  честно отображается в интерфейсе. Для сотен тысяч записей понадобится
  нативный драйвер; интерфейс `SqlDriver` под это уже написан.
- Автообновление приложения, облачные бэкапы и перенос на Tauri/React Native
  не сделаны.
- Поле `repository` в `package.json` содержит заглушку
  (`https://github.com/yourusername/nexus-finance`) и требует замены на
  настоящий адрес.

## Лицензия и доступ

**Закрытая бета-версия с ранним доступом.** Открытая лицензия на код не
выбрана и не планируется: в `package.json` указано `"UNLICENSED"` —
штатная пометка npm «прав на использование кода не предоставляется».
Исходный код лежит в приватном репозитории `dev-aitechpro`; наружу
раздаются только собранные установщики.

- **Что бесплатно.** Установка и использование текущей сборки —
  `1.0.0-beta.1` и её последующих версий, без ограничения по сроку.
- **За что берут деньги.** Доступ к новым сборкам — в обмен на оплату
  платного поста автора на Boosty:
  <https://boosty.to/kpavels1997/donate>. Каждая новая сборка выходит
  отдельным постом, оплата разовая: подписки и автопродления нет, каждый
  следующий релиз — снова отдельная оплата. Оплата даёт новые сборки,
  приоритетные ответы в Telegram и влияние на приоритеты доработок. Это
  платная поддержка автора, а не покупка кода: прав на исходники она не
  даёт, и доступ к сборкам, вышедшим до оплаты, условиями не обещан.
- **Распространять программу нельзя.** Условия запрещают выкладывать установщик
  или APK куда бы то ни было, передавать копию третьим лицам, продавать,
  переименовывать, декомпилировать и включать в состав другого продукта —
  независимо от того, платно это или бесплатно. Распространять эту программу
  вправе только автор, и запрет бессрочный.
- **Где написано подробно.** [`license.txt`](license.txt) — условия
  использования; они же показываются внутри программы: ссылка «Условия» в
  футере и кнопка в «Настройках». Обоснование решения, обязательства по
  лицензиям зависимостей и
  порядок действий при выходе из беты —
  в [docs/Лицензирование.md](docs/Лицензирование.md).
- **Как приходят обновления.** Только по вашему решению: в настройках есть
  кнопка «Проверить обновления», и ничего не происходит, пока её не нажать.
  Автоматических проверок, фоновой загрузки и установки при выходе из
  программы в сборке нет. На Android приложение всё равно не может заменить
  себя — оно сообщит о новой версии и откроет страницу релиза в браузере,
  а APK поставите вы сами. Перед обновлением сделайте экспорт: формат базы
  между сборками постоянным не считается.
- **Пользователям.** Личных данных это не добавляет: приложение не
  работает с сервером, телеметрии нет, подписка автора данные не
  синхронизирует. Данные и резервные копии — только на устройстве, см.
  раздел «Где лежат данные» выше.
