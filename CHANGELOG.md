# Changelog

Все значимые изменения проекта NEXUS Finance фиксируются в этом файле.

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии —
[Semantic Versioning](https://semver.org/lang/ru/): MAJOR — несовместимые изменения данных или
формата, MINOR — новая функциональность, PATCH — исправления. Каждый пункт описывает, **что
изменилось и почему это важно пользователю**, а не список имён файлов. Текущая версия —
`1.0.0-beta.1` (поле `version` в `package.json`; в `src` она не продублирована, а подставляется
при сборке).

Нумерация версий и даты: `1.0.0` была **запланированным** номером, под который писался код, но
не выпускалась — публикации не было, запись фиксирует состояние репозитория на момент
составления. Первой настоящей публикацией стала бета `1.0.0-beta.1` (ранний доступ,
установка бесплатна, доступ к новым сборкам — по подписке автора). По правилам SemVer
`1.0.0-beta.1` считается **раньше** `1.0.0`, поэтому записи в файле расположены от новых к
старым, а `1.0.0` остаётся как запись о внутренней вехе, а не о выпуске.

## [1.0.0-beta.1] - 2026-09-28 (первая бета, ранний доступ)

### Релизные сборки Windows и Android

- **Приложение теперь устанавливается как обычная программа.** Появилась команда
  `npm run build:win`: она собирает установщик NSIS и portable-версию для Windows x64
  (плюс распакованную сборку для отладки). Раньше установщик в этой среде не
  собирался вовсе, и пользователю было нечего поставить. Проверено запуском из
  отдельного каталога без папки проекта: приложение стартует, читает и пишет базу,
  трей работает, все девять методов `window.electronAPI` на месте.
- **Появился настоящий APK для Android** (`npm run build:apk` и
  `npm run build:apk:debug`). Раньше мобильной сборки не существовало: в
  репозитории не было ни каталога `android/`, ни конфигурации мобильной платформы,
  ни сборочных файлов Gradle, ни манифеста. Теперь release-APK (4,39 МБ) подписан
  самоподписанным ключом, debug-APK (6,73 МБ) собирается отладочным ключом.
  Иконки приложения — те же, что и на Windows: скрипт конвертирует `public/favicon.ico`
  в PNG всех плотностей, вместо дефолтных иконок Capacitor.
- **В сборку Windows попал `public/favicon.ico`, которого раньше там не было.** Без него
  главный процесс не находил иконку — а значит, не работали бы ни иконка окна, ни
  значок в трее.
- **Сборка больше не качает Electron заново** — берёт локально установленный
  (`node_modules/electron/dist`). Раньше зеркала отдавали архив, но не файл
  контрольных сумм, на котором загрузка падала; из-за этого установщик и не
  собирался.
- **В свойствах `.exe` и в списке «Программы и компоненты» появилось описание** —
  в `package.json` добавлено поле `description`; раньше обе строки были пустыми.
- **Сообщения рендерера больше не пропадают в релизной сборке.** Обработчик
  `console-message` в главном процессе писал только в консоль, которой в собранном
  приложении нет, — падение или ошибка не оставляли следов. Теперь те же сообщения
  идут и в файл журнала.
- **Распознавание чеков перестало падать из-за политики безопасности.** В
  `script-src` добавлен `cdn.jsdelivr.net`: движок распознавания создаёт воркер из
  `blob:`-URL, а тот внутри себя подгружает скрипт с этого хоста через
  `importScripts`, который проверяется именно этой директивой. Раньше хост был
  разрешён только в `connect-src`, из-за чего воркер не стартовал — то есть
  сканирование чеков было сломано и в Electron, и на Android. Теперь работает везде.

### Android: переписан мост доступа к платформе

- **Кнопка «Назад» наконец заработала.** Раньше подписка шла на DOM-событие
  `backbutton` — соглашение первой версии мобильного контейнера; современный
  контейнер такого события не отправляет, поэтому подписки не было вовсе, и нажатие
  просто уходило назад по истории. Теперь это штатный `App.addListener("backButton")`:
  «назад» закрывает открытое окно, затем возвращает на главный экран, а на главном
  отдаёт системе.
- **Мост уведомлений на Android переписан.** Раньше код обращался к удалённому в третьей
  версии контейнера API и тихо получал `undefined`. Теперь используется штатный
  плагин локальных уведомлений с запросом разрешения и честным показом отказа.
  **Уточнение после проверки на устройстве:** мост работает корректно, но
  **приложение его нигде не вызывает** — все сообщения пользователю идут
  внутренними всплывающими подсказками. Разрешение `POST_NOTIFICATIONS`
  объявлено, запроса не происходит, системных уведомлений не приходит. См.
  «Мобильная проверка на реальном устройстве» ниже.
- **Экспорт в файл на Android больше не «успевает» на пустом месте.** Раньше
  браузерная загрузка файла в WebView не выполняется вовсе, но функция сообщала об
  успехе. Теперь файл пишется настоящим плагином файловой системы (сначала в
  «Документы», при запрете scoped storage — во внешнюю папку приложения) и отдаётся
  системным меню «Поделиться».
- **Версия приложения в настройках на Android настоящая**, а не константа
  «1.0.0» из веб-версии: берётся из манифеста, поэтому не будет врать после первого
  же релиза.
- **Пункт «Открыть папку с данными» на Android убран** — открывать нечего, у WebView
  нет пользовательской папки. Вместо кнопки показан реальный адрес хранилища внутри
  приватного хранилища приложения; раньше там был выдуманный путь к файлу, которого
  не существует.
- **Ошибки больше не глотаются молча:** каждая пишется в консоль с префиксом, а
  ложные обещания возможностей убраны — слой сам сообщает, что умеет, по факту
  наличия плагина в сборке.
- Подпись release настраивается отдельно и лежит вне репозитория (файл с паролями и
  сам ключ исключены из системы контроля версий). Если их нет, release собирается
  неподписанным, а не падает.

### Мобильная проверка на реальном устройстве

Впервые приложение запущено не в браузере и не в Electron, а на настоящем
телефоне: **Infinix X6858, Android 16 (SDK 36)**, экран 1080×2436 при плотности
440 — то есть ≈393 CSS-пикселя по ширине. Установлен подписанный release-APK.
Приложение запустилось, база работает, в журнале ошибок нет. Ниже — что при этом
оказалось не так и что исправлено. Все правки в мобильном интерфейсе не
затрагивают десктоп: правила касательного ввода живут в `@media (pointer: coarse)`.

- **Суммы показывали «плашку» вместо знака рубля.** В системном шрифте телефона нет
  глифа ₽ (U+20BD), и WebView рисовал на его месте прямоугольник: `557 885 ▯`.
  Подменить символ после форматирования нельзя — `Intl.NumberFormat` со
  `style: "currency"` подставляет знак валюты сам. Теперь новая функция
  `readSymbol()` (`src/lib/utils.ts`) определяет наличие глифа измерением ширины
  в канвасе (сравнение с заведомо отсутствующим символом U+FFFF, результат
  кэшируется) и возвращает текстовую замену из `CURRENCY_TEXT` («руб.», «USD»,
  «EUR», «GBP»); `formatNumber` форматирует число отдельно от валюты и дописывает
  знак сам. Экран настроек тоже идёт через `readSymbol`. На устройстве теперь
  «557 885 руб.».
- **Нижняя навигация не помещалась — часть разделов была недоступна.** Девять
  пунктов в 393 пикселя — это около 2,5 экрана горизонтальной прокрутки без
  индикации; «Настройки» и «Сканер» нельзя было открыть без догадки. Теперь в
  ленте пять пунктов (Обзор, Транзакции, Платежи, Подтвердить, Ещё) колонками
  равной ширины (`grid-auto-columns: minmax(0, 1fr)`, а не `1fr` — иначе длинная
  подпись распирает ячейку и прокрутка возвращается), иконка над подписью,
  `min-height: 48px`, бейдж неподтверждённых перенесён на угол иконки. Пункт
  «Ещё» открывает новую компоненту `BottomSheet` (роль `dialog`, `aria-modal`,
  `FocusTrap`, затемнение, крестик, `Escape`, все девять разделов, текущий помечен
  галочкой) — иными словами, на телефоне доступны все разделы, а не четыре.
- **Кнопка «Назад» научилась закрывать диалоги.** Раньше открытое окно можно было
  закрыть только `Escape`, а на телефоне такой клавиши нет: нажатие уводило с
  приложения, компонент с диалогом размонтировался, и введённое терялось.
  Появился стек открытых оверлеев (`src/hooks/useOverlayStack.tsx`): верхний из
  открытых закрывается первым — так же, как в браузере и в самом Android.
  Обработчик в приложении по-прежнему один.
- **Перехват кнопки «Назад» перенесён на уровень модуля** (`AppShell.tsx`).
  Вторая нативная подписка на `backButton` недопустима: событие раздаётся всем
  подписчикам, а мост при возврате `false` выпускает нажатие в систему — «Назад»
  со шторкой закрыл бы её и вышел бы наружу. Теперь нативная подписка ровно одна,
  а шторка отвечает в приоритетном слоте. Проверено на устройстве по всей
  цепочке: шторка → модалка транзакции → возврат на Обзор → выход из приложения.
- **Всплывающее сообщение закрывало навигацию на четыре секунды** — то есть
  пропадал единственный канал обратной связи. Тост стоял в `z-70` поверх ленты
  вкладок (`z-45`); теперь на телефоне он поднят над лентой и уведён от краёв
  (зоны жестов), а сам контейнер помечен `aria-live="polite"`.
- **Клавиатура в модалке гасла сразу после открытия.** `Modal` фокусировал первый
  интерактивный элемент в порядке документа, а в шапке первым стоит крестик:
  React открывал клавиатуру на поле суммы, а через 100 мс фокус уезжал на крестик
  и системная клавиатура закрывалась. Теперь на устройствах с `pointer: coarse`
  фокусируется первое **поле ввода**, с задержкой 260 мс (дать клавиатуре подняться);
  на остальных — как было, кнопка.
- **Липкая шапка уезжала под строку состояния.** `env(safe-area-inset-*)` не
  использовался нигде, а при `targetSdk 35+` приложение рисуется под системными
  панелями. Введены переменные `--sat/--sar/--sab/--sal` в `:root` и применены в
  `.mobile-topbar`, `.mobile-nav` и `.app-main`; на десктопе и в старых WebView они
  равны нулю.
- **Зоны нажатия были меньше 44 пикселей, а кегль в полях — 14,4 px** (из-за
  последнего Chrome увеличивает масштаб при фокусе). Исправлено **только** для
  `@media (pointer: coarse)`: десктоп не тронут.
- **Средний уровень устройства не был описан ни одним правилом** — телефон со
  средним запасом памяти получал полные эффекты. Добавлена деградация фоновых
  свечений и размытия карточек для `mid`; в правило для `low` добавлены
  `.mobile-nav` и `.mobile-topbar`.
- **График нельзя было «протереть» пальцем, тултип залипал.** События мыши
  заменены на pointer-события, добавлен `touch-action: pan-y`.
- **Смена вкладки не сбрасывала прокрутку:** `window.scrollTo` был пустым вызовом
  (корневой контейнер — `h-screen` с `overflow: hidden`). Теперь скроллится
  контейнер `.app-main`.
- **Google Backup забирал всю базу — и мог вернуть её на другом устройстве.**
  В манифесте стояло `allowBackup="true"` без правил, поэтому приватное хранилище
  (IndexedDB с базой плюс дубль в `localStorage`) уходило в облако и
  восстанавливалось молча. Исправлено: `allowBackup="false"`, добавлены
  `res/xml/data_extraction_rules.xml` и `res/xml/backup_rules.xml`, запрещающие и
  облачную копию, и перенос «телефон → телефон». Проверено на устройстве — пакета
  нет в списке бэкапа. **Следствие, о котором важно знать пользователю:** раз
  система больше не восстанавливает базу, экспорт из Настроек — единственная
  страховка, и он теперь обязателен, а не рекомендация.
- **Три разрешения были объявлены, но не использовались.** `WAKE_LOCK`,
  `RECEIVE_BOOT_COMPLETED` и `VIBRATE` удалены через `tools:node="remove"`
  (проверено по исходникам плагина: wakelock не берётся нигде, обработчик после
  перезагрузки получает пустой список, вибрация включается только явным вызовом).
  Заодно добавлены `android:usesCleartextTraffic="false"` и
  `android:windowSoftInputMode="adjustResize"`.

Что проверено и работает на устройстве: перехват «Назад» по всей цепочке; экспорт
JSON (файл 52 КБ в публичной папке «Документы», валидный, все 130 транзакций);
настройки показывают «Android · v1.0.0» и настоящий путь
`indexeddb://nexus-finance/db.sqlite`, хранилище «постоянное», журнал SQLite в
режиме WAL; иконки категорий, графики, список транзакций, модалка транзакции.

Сознательно **не** сделано: сжатие R8 (`minifyEnabled`) осталось выключенным.
Оно дало бы экономию 1–1,5 МБ, но требует полной регрессии на устройстве — при
неправильных keep-правилах ломаются вызовы нативных мостов. Это отдельная задача с
регрессией, а не оптимизация по умолчанию. `SCHEDULE_EXACT_ALARM` оставлен как
«будет удалён при включении отложенных уведомлений»: сейчас приложение шлёт только
немедленные уведомления (`isExactNotification: false`).

**Требует проверки** (на устройстве не проверялось): камера и распознавание чеков
(нужен доступ к `cdn.jsdelivr.net`), альбомная ориентация, анимация predictive-back,
отправка файла системным меню «Поделиться» (в том числе открывается ли файл из
публичной папки) и несколько разных устройств — APK проверен на одном, Infinix
X6858 / Android 16.

### Обновление программы — только по решению пользователя

- **В приложении появилась кнопка «Проверить обновления»** (Настройки). Новые версии публикуются в
  GitHub Releases, и пользователь сам решает, забирать их или остаться на текущей: автоматической
  проверки, фоновой загрузки и установки при выходе из программы нет ни в одной сборке.
- Проверка, загрузка и запуск установщика выполняются только по нажатию: «Проверить» → «Скачать»
  → «Установить и перезапустить», с индикатором прогресса. Кнопки появляются по мере
  готовности, а не заранее.
- **Сборка не подписана** (сертификата нет), поэтому подпись установщика проверить некому.
  Приложение не сообщает об успехе: оно прямо предупреждает, что подпись не проверена, и
  предлагает скачать вручную со страницы релиза.
- **Обновление по требованию «без разрешения пользователя» технически недоступно для APK**:
  приложение не может заменить себя. На Android проверка сообщает о наличии новой версии и
  открывает страницу релиза в системном браузере, а установку нового APK пользователь делает
  сам.
- Репозиторий исходников закрыт, поэтому автоматическая проверка обновлений не сработает без
  входа в учётную запись. Приложение не притворяется, что всё в порядке: объясняет причину и
  предлагает открыть страницу релиза в браузере. Токен в приложение не встраивается намеренно.
- **Первое обновление скачает установщик целиком (~100 МБ)**, а не дельту: дельта считается от
  `.blockmap` предыдущего релиза, а предыдущего не было. Со второго обновления объём
  сокращается.

### Условия бета-раннего доступа

- **Условия использования определены** — приложение распространяется как закрытая бета с ранним
  доступом, а не под открытой лицензией. `license.txt` (его показывает установщик) описывает:
  что это бета и данные могут измениться, установка бесплатна, а доступ к новым сборкам даётся в
  обмен на подписку автора на Boosty, где хранятся данные и как их сохранить (экспорт заменяет
  резервное копирование: облачный бэкап запрещён настройками приложения).
- Отсутствие гарантий, ограничения (только личное использование, без перепродажи), что
  происходит при прекращении раннего доступа и как отказаться от условий — тоже в `license.txt`.
- **Тон сознательно человеческий.** Про обработку персональных данных не написано ничего:
  приложение ничего никуда не отправляет, выдумывать правовые конструкции под несуществующую
  обработку не нужно. Единственное исходящее соединение — CDN для OCR-модуля сканера чеков, и оно
  названо прямо.
- **Выявлена обязанность, которой раньше не занимались:** уведомлений об авторских правах
  сторонних авторов в сборке нет, а у части зависимостей (Apache-2.0) нет файлов `NOTICE`.
  Лицензии зависимостей требуют их сохранения независимо от лицензии самого продукта — список
  того, что нужно добавить, приведён в `docs/Лицензирование.md`.
- Ранее в трёх местах репозитория было указано MIT, затем указание сняли как преждевременное
  (`UNLICENSED`, `license.txt` был заглушкой). Теперь решение принято, но не в пользу открытой
  лицензии: исходники остаются закрытыми, пользователям раздаются собранные установщики.

## [1.0.0] — 2026-09-27 (дата составления записи; версия не выпускалась)

### Хранилище

- Слой хранения перенесён с `localStorage` на SQLite (движок `sql.js`, WebAssembly). Раньше данные
  лежали в хранилище WebView и могли молча пропасть; теперь это база со схемой, версией схемы,
  шагами миграций, индексами по фильтруемым полям и проверкой целостности.
- Запись дифференциальная, по идентификатору: 1000 записей сохраняются примерно за 16 мс, и
  удельная стоимость записи падает с ростом объёма вместо того, чтобы расти.
- Введена единая очередь операций записи, очистки и транзакций. Раньше два автосохранения
  сливались в одну транзакцию, чужой откат стирал уже возвращённый результат, а удаление
  «устаревших» строк сносило только что записанное. Вложенные транзакции реализованы через
  точки сохранения: сохранение снимка базы внутри транзакции больше не закрывает её.
- Снимок базы пишется по цепочке: файл в папке приложения → IndexedDB → `localStorage` →
  память. Каждая ступень — осознанная деградация с сохранением данных, а не молчаливая потеря.
- Успех записи в IndexedDB определяется по завершению транзакции, а не по событию запроса:
  раньше интерфейс показывал «сохранено» для данных, которые в базу не попали. Резервная
  копия при пустой основной опрашивается и удаляется после успеха — раньше свежая копия
  проигрывала старой.
- Перенос данных из старого хранилища идёт одной транзакцией; битый один из ключей больше не
  обрывает перенос целиком, исходные данные хранятся ещё 30 дней для отката, и в настройках
  видно, сколько дней осталось.
- «Очистить все данные» больше не «воскресает»: очистка дожидается завершения записи, а
  служебные отметки миграции переживают очистку, чтобы удалённые данные не вернулись из
  старого хранилища.
- Ошибка чтения базы больше не выглядит как «база пуста»: приложение сообщает об ошибке и
  предлагает повторить чтение, блокируя автосохранение — раньше на место реальных данных
  могли встать демонстрационные.
- Статус «данные сохранены» стал правдивым (по типу хранилища и результату последней записи),
  а ошибка записи файла поднимается как ошибка, а не игнорируется. Добавлено сжатие базы:
  автоматически после очистки и по кнопке в настройках — 204 КБ превращаются в 152 КБ.
- Импорт бэкапа стал устойчивее: достаточно одной узнаваемой части данных, а не строгого набора
  коллекций — раньше бэкап без списка операций отбраковывался целиком вместе с подписками, целями
  и бюджетами; настройки при слиянии больше не сбрасываются.
- Облачные бэкапы (Яндекс Диск) удалены вместе с обменом токеном: токен хранился во временном
  хранилище рядом с финансовыми данными, а под протоколом `file://` вход не проходил вовсе.
  Остались локальный экспорт и импорт, работающие без сети и аккаунтов.

### Анимации и производительность

- Анимации переведены на расчёт по реальному времени, а не по числу кадров: скорость задаётся
  в единицах в секунду, поэтому на 60 и 144 Гц анимация идёт одинаково (закреплено тестами), а
  длинный кадр вроде сворачивания вкладки обрезается, чтобы после возвращения не было «прыжка».
- Движение выполняется только по свойствам, не вызывающим пересчёт вёрстки: столбцы графиков
  рисуются сразу в конечных координатах и «вырастают» масштабом, а фоновые линии идут сдвигом
  вместо изменения координаты.
- Графики появляются и в фоновой вкладке: раньше появление зависело только от механизма
  отрисовки кадров, который в неактивной вкладке не срабатывает. Добавлена страховка по таймеру.
  При отключённых анимациях или слабом устройстве полоса прогресса показывает конечное
  значение, а не застревает на нуле; анимации модуля отменяются перед следующей, поэтому
  они не накапливаются и не конфликтуют.
- Одновременных появлений ограничено, чтобы уведомления не превращались в кашу; изменение чисел
  в интерфейсе переведено на общий цикл отрисовки и на слабом устройстве выдаёт результат сразу.
- Введено определение уровня устройства (память, ядра, системная настройка движения): приложение
  само выбирает облегчённый режим, который можно принудительно включить ссылкой в адресе
  страницы. Он отключает не только тени и размытие, но и появление окон, вспышки котировок,
  пульсацию точки статуса и развёртку сканера.
- При системной настройке «меньше движения» обнуляется и задержка появления карточек — раньше
  карточки с задержкой до 380 мс оставались невидимыми вообще. Фоновые слои интерфейса (сетка,
  два свечения, сканирующая линия) возвращены и двигаются медленным дрейфом без пересчёта вёрстки;
  починены цвета навигации и футера, которые раньше не применялись вовсе, из-за чего подсветка
  при наведении не работала.
- Возвращены отклик на нажатие, анимации появления и исчезновения у окон и уведомлений, анимация
  индикатора активной вкладки; исправлена потеря основного цвета активного пункта при наведении и
  дефект облегчённого режима списков, гасившего разделители у всех чётных строк. Восьми экранам
  назначена отложенная загрузка: сканер документов с распознаванием больше не входит в стартовый объём.
  Добавлено введение при первом запуске — четыре шага на русском, отметка о прохождении хранится в базе.

### Подписки и регулярные платежи

- Удаление операции из подписки больше не возвращает её к подтверждению: месяц закрывается датой
  удалённой операции, раньше подписка «вылезала» обратно в список неоплаченных сама по себе.
- Платёж следующего месяца создаётся заранее, чтобы пропущенный месяц не потерялся, но
  показывается отдельным блоком «Запланировано» и не попадает ни в журнал операций, ни в
  счётчик неоплаченных: планирование видно, но не выглядит как долг.
- Перед удалением показывается подтверждение с объяснением последствий; массовое удаление работает
  по тем же правилам. При удалении подписки или обязательного платежа задаётся вопрос: перенести
  на следующий месяц (появится в разделе «Запланировано» и потребует подтверждения в срок) или
  удалить полностью вместе со всеми записями. Выполняется именно выбранный вариант.
- У запланированного платежа появилась кнопка удаления: он не попадает в журнал, и без неё такой
  платёж оставался бы на экране навсегда.
- Исправлена ошибка, из-за которой «Удалить выбранные» ничего не удаляла: панель массового
  выделения и журнал операций держали два разных состояния выделения. Теперь состояние одно.
- Иконка подписки в списке берётся из категории, а не задана жёстко, — подписки больше не сливаются
  с прочими операциями; у названия цели ограничена длина, а имя из данных перенесено из заголовка
  окна в его тело.

### Интерфейс и вёрстка

- Категория больше нигде не выбирается выпадающим системным списком: добавлен выбор плиткой с
  иконкой и цветом категории. В системном списке иконку показать невозможно, поэтому её в форме
  не было вовсе.
- Карточка «Расходы по категориям» больше не вылезает за свои границы: кольцо и легенда всегда
  расположены друг под другом. Раньше на широком окне легенда выезжала за карточку примерно на
  60 пикселей и наезжала на соседний блок.
- В журнале операций выровнены все строки: у платежей в ожидании не было checkbox'а, из-за чего
  иконки и подписи съезжали влево, а длинные описания выдавливали соседние колонки. Границы карточек
  стали заметнее — введена отдельная переменная и тонкий внутренний блик, раньше контур был почти
  не виден и соседние карточки сливались.
- Контур шестиугольных карточек перенесён на внутреннюю тень: обрезка формы срезала обычную рамку
  по диагоналям. Теперь контур идёт ровно по контуру, включая срезанные углы, а в светлой теме
  смешивается с цветом текста, иначе насыщенно-светлые цвета были почти не видны.
- Подсказки на графиках не выходят за пределы карточки (в одной из тем их углы срезались, а сами
  подсказки наезжали на соседнюю карточку), подписи осей увеличены и разнесены — раньше на телефоне
  они были нечитаемы и накладывались.
- Длинные суммы корректно переносятся, а длинные названия обрезаются (раньше обрезка не работала,
  потому что контейнер не позволял ей сжиматься); формы переведены на одну колонку на узких
  экранах, панель массового выделения переносится, добавлена «безопасная зона» для телефонов с
  вырезом экрана.
- Возвращена мобильная навигация: раньше при узком экране сайдбар скрывался, а ленты не было —
  навигации не оставалось вовсе. Проверено в браузере: ни один элемент не выходит за правый край
  окна ни на одном из восьми экранов, включая самый узкий контейнер.
- В футере вместо эмодзи стоят настоящие значки: значок Telegram — штатный глиф фирменным
  цветом; значок платёжной платформы — монограмма фирменным цветом, потому что официальный
  векторный знак проверить не удалось (когда появится официальный файл, меняется только он,
  интерфейс не затрагивается).
- В настройках раздел «Хранилище данных» показывает реальное состояние базы: драйвер, режим
  журнала, версия схемы, размер файла, статус переноса данных, срок отката, режим графики,
  ошибки чтения и записи и обслуживание базы.

  тесты + сборка + проверка артефакта; отдельно — проверка протокола `file://` и проверка рабочей базы
  в профиле пользователя: схема версии 1, все таблицы на месте, целостность проходит.

### Исправления сборки

- Прод-сборка не запускалась вообще: в конфигурации сборки был список системных модулей,
  помеченных как внешние, и в готовом файле оставался голый импорт такого модуля, из-за чего
  страница падала при загрузке. Список убран, сборка работает. Dev-сервер при этом отдавал
  ошибку 500 при загрузке базы: движок в формате WebAssembly ошибочно воспринимался как
  исходник; обойдено подключением базы как встроенных данных — работает в dev, в сборке и
  при открытии из файла.
- Приложение молча уходило на запасную, более тяжёлую сборку базы, и это было видно только по
  сетевым запросам. Теперь основная сборка действительно используется. Её наличие — известное
  ограничение: 1.3 МБ в поставке ради случая, когда WebAssembly недоступен, из-за чего файл
  приложения весит около 2.9 МБ (1.07 МБ в сжатом виде).

## Известные ограничения

Подробный разбор — в `docs/Решение-проблем.md` и `docs/Выполнение-ТЗ.md` (разделы 7, 7а и 7б).

- **Распознавание чеков требует сети.** Движок распознавания подгружает рабочий модуль и языковые
  данные из внешнего источника, поэтому в настольной версии офлайн оно не работает. Лечится только
  встраиванием языковых данных — это около 15 МБ.
- **Ни установщик Windows, ни APK не подписаны.** Для Windows нужен сертификат подписи кода
  (OV или EV), иначе SmartScreen показывает «Неизвестный издатель». Для Android ключ есть,
  но он самоподписанный: Google Play его не примет без загрузки ключа в Play App Signing,
  а `versionCode` в `android/app/build.gradle` приходится поднимать вручную. Текущая цель
  распространения — ручная установка `.apk`.
- **APK не проверялся на устройстве или эмуляторе.** В среде нет ни образа системы, ни
  драйвера гипервизора, AVD не создавались. Сборка сверена по составу пакета (идентификатор,
  версия, уровни SDK, разрешения, совпадение веб-ассетов с `dist/`), но не запущена.
- **Сборки требуют сети при первом запуске:** `build:win` скачивает компоненты сборщика
  установщика, `build:apk` — артефакты Gradle. Повторные сборки используют кэш.
- **Код закрыт, условия использования определены.** `license.txt` — условия бета-раннего
  доступа, `package.json` → `UNLICENSED`. Пользователь получает собранный установщик, а не
  исходники. См. `docs/Лицензирование.md`.
- **Уведомлений об авторских правах сторонних авторов в сборке нет.** Лицензии зависимостей
  (Apache-2.0, MIT) требуют их сохранять, часть пакетов поставляется без файла `NOTICE`. Для
  закрытого продукта, который раздаётся подписчикам, это обязанность, и она пока не выполнена.
- **Проверка обновлений требует доступа к закрытому репозиторию.** Без входа в учётную запись
  GitHub приложение не получит сведения о релизе и честно сообщит об этом, предложив открыть
  страницу релиза в браузере. Вшивать токен в приложение нельзя — он уедет к каждому
  пользователю.
- **Обновление Android невозможно в принципе:** APK не может заменить себя. Приложение
  сообщает о новой версии и открывает страницу релиза, установку делает пользователь.
- **База целиком живёт в памяти,** а на диск пишется снимок: режим журнала запрашивается, но на базе в
  памяти он не даёт настоящего поведения — это честно показано в интерфейсе. Для сотен тысяч записей нужен
  нативный драйвер; контракт драйвера подготовлен. **Постраничная загрузка не доведена до экранов:**
  индексы и ограничение выборки работают на уровне базы, но список операций читается целиком и режется
  в памяти.
- **Очистка данных приложения на Android стирает базу:** она лежит в IndexedDB внутри приватного
  хранилища WebView, и очистка удаляет её вместе с приложением. На Windows файл базы в `userData`
  переживает очистку кэша. Лечится нативной файловой БД или регулярным экспортом.
- **Автообновление приложения не сделано** (нужен внешний компонент и сервер релизов; подготовлено только
  место — слой доступа к платформе). **Облачных бэкапов нет** — по решению владельца продукта модуль
  Яндекс Диска удалён; остались локальный экспорт и импорт в JSON и файл базы, оба работают без сети.
- **Полный переход на нативный кроссплатформенный слой (Tauri/React Native) не выполнен** — нужен
  внешний тулчейн; вместо имитации перехода подготовлены контракты драйвера базы и доступа к платформе.
  Git-хук для обновления карты проекта тоже не настроен: каталог не под системой контроля версий.
