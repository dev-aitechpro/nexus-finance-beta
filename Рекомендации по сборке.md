1. Ключевой принцип: «Веб — источник истины»
text
┌─────────────────────────────────────────────────────────┐
│  ЭТАП 1: Веб-билд (ядро логики, UI, состояние)          │
│  → один самодостаточный артефакт (index.html / SPA)     │
│  → вся бизнес-логика, типы, утилиты, тесты — здесь      │
└──────────────────────────┬──────────────────────────────┘
                           │  переиспользование без изменений
                           ▼
┌─────────────────────────────────────────────────────────┐
│  ЭТАП 2: Обёртки под платформы                          │
│  Desktop (Electron/Tauri) · Android (Capacitor/Cordova) │
│  iOS · PWA · CLI                                        │
│  → добавляется только адаптер хранилища + нативные API  │
└─────────────────────────────────────────────────────────┘
Правило: ядро (UI + логика + типы) не знает, на какой платформе оно запущено. Платформенные различия инкапсулируются в адаптерах (хранилище, файловая система, диалоги, обновления).

2. Архитектурный каркас
2.1 Слои
Слой	Ответственность	Платформозависимость
UI-компоненты	Отображение, взаимодействие	Нет (React/Vue/Svelte)
Состояние (store)	Данные, миграции, селекторы	Нет (Zustand/Redux/Pinia)
Утилиты (utils)	Чистая логика: парсинг, экспорт, переменные, рендер	Нет
Типы (shared/types)	Единая схема данных	Нет
Адаптер хранилища	Персистентность	Да — подменяется
Платформенный мост	Диалоги, обновления, файлы	Да — подменяется
2.2 Контракт адаптера хранилища
ts
interface StorageAdapter {
  get(key: string): Promise<unknown>;
  set(key: string, value: unknown): Promise<void>;
  delete(key: string): Promise<void>;
  // опционально
  export?(): Promise<Blob | string>;
  import?(data: Blob | string): Promise<void>;
}
Реализации:

Web: localStorage / IndexedDB / in-memory (для тестов и SSR)

Desktop (Electron): electron-store → файл в %APPDATA%

Desktop (Tauri): tauri-plugin-store / файл на диске

Android/iOS (Capacitor): @capacitor/preferences / SQLite

PWA: IndexedDB + Service Worker

2.3 Контракт платформенного моста
ts
interface PlatformBridge {
  showSaveDialog(options): Promise<string | null>;
  showOpenDialog(options): Promise<string | null>;
  readFile(path): Promise<string>;
  writeFile(path, data): Promise<void>;
  checkForUpdates?(): Promise<UpdateInfo | null>;
  getVersion(): string;
}

4. Пошаговый процесс сборки
Шаг 1. Веб-ядро
Спроектировать схему данных с версионированием (version: N) и миграциями.

Реализовать UI, состояние, утилиты — без прямых обращений к localStorage/window/document вне UI-слоя.

Вынести все платформенные вызовы за интерфейсы (StorageAdapter, PlatformBridge).

Настроить сборку в единый автономный артефакт (один index.html или SPA-бандл).

Покрыть тестами: утилиты, store, миграции, XSS-безопасность рендера, импорт/экспорт.

Шаг 2. Десктоп-обёртка
Создать папку electron/ (или src-tauri/) с main-процессом.

Подключить адаптер хранилища к файлу (electron-store, Tauri store).

Заменить веб-диалоги на нативные через IPC.

Подключить автообновление (канал — GitHub Releases / свой сервер).

Настроить сборку установщика (NSIS, DMG, AppImage, MSI).

Добавить подтверждение обновлений (не автоустанавливать без согласия).

Шаг 3. Мобильные платформы
Обернуть веб-билд в Capacitor/Cordova.

Заменить адаптер хранилища на @capacitor/preferences или SQLite.

Подключить нативные диалоги выбора файлов.

Настроить сборку AAB/APK, подпись, публикацию.

Для iOS — аналогично через Capacitor + Xcode.

Шаг 4. Прочие платформы
PWA: манифест + Service Worker + оффлайн-кэш.

CLI: переиспользовать утилиты и store (headless-режим).

Расширения браузера: тот же UI + chrome.storage.

5. Обязательные практики
5.1 Версионирование схемы данных
text
version: 1 → 2 → 3 ...
При загрузке старых данных — миграция без потери данных. Числовые id → строки, ссылки по имени → стабильные id, дефолты новых полей.

5.2 Единый формат экспорта/импорта
Расширение .prmt (JSON) — полная сериализация (данные + структура + метаданные).

Импорт .md/.txt — одиночная запись.

Диалог объединения баз при конфликтах: пропустить / переименовать / заменить / дублировать.

Некорректные записи не «роняют» импорт — перечисляются в отчёте.

5.3 Безопасность
Markdown-рендер: экранирование ввода, разрешены только http, https, mailto, относительные ссылки.

Запрет javascript: и data:.

Покрытие XSS-кейсов тестами.

5.4 Самостоятельность веб-билда
После build артефакт открывается двойным щелчком, без хостинга.

В веб-режиме нет обращений к web-хранилищам, если используется in-memory адаптер (для тестов/SSR).

5.5 Динамическая версия
Версия в UI берётся из app.getVersion() (Electron) / package.json / Tauri API — не хардкодится, чтобы не рассинхронизироваться со сборкой.

5.6 Горячие клавиши — единая точка регистрации
Один hook/module (useGlobalHotkeys.ts) — список в UI синхронизирован с реализацией.

Не перехватывать ввод во время набора текста.

5.7 Адаптивность UI
min-w-0/min-h-0 в flex-цепочках.

Автоперенос длинных слов, ссылок, кода, таблиц.

Модалки ограничены max-width: 100%.

Названия элементов: подбор размера шрифта, перенос до N строк, tooltip + aria-label.

5.8 Тесты
Утилиты: переменные, рендер, поиск, миграции.

Store: CRUD, каскады, перемещение, импорт.

Импорт/экспорт: валидация, конфликты, действия объединения.

Smoke-тест UI: горячие клавиши, контекстное меню, режимы редактора.

7. Чек-лист перед выпуском
□ Веб-билд — один автономный файл, открывается без сервера
□ Все платформенные вызовы — за интерфейсами
□ Схема данных версионирована, миграции протестированы
□ Экспорт/импорт покрывает структуру и метаданные
□ XSS-защита в рендере, тесты на javascript:/data:
□ Версия в UI динамическая
□ Горячие клавиши — единая точка регистрации
□ UI адаптивен: нет расползания, переносы, tooltip
□ Тесты: утилиты, store, импорт/экспорт, smoke UI
□ Автообновление — с подтверждением пользователя
□ Импорт не «роняет» приложение на некорректных данных
□ Существующие данные не удаляются при слиянии баз
8. Что можно переиспользовать напрямую
Паттерн «ядро + адаптеры» — подходит для заметок, таск-менеджеров, редакторов, каталогов, конфигураторов.

Формат .prmt — замените на свой доменный формат (.note, .task, .cfg).

Диалог объединения баз — универсален для любых импортов с конфликтами.

Миграции схемы — обязательны для любого долгоживущего приложения.

In-memory адаптер — для тестов и SSR.
